# 网站收藏管理：首版需求规格

确认日期：2026-10-09。功能需求、前端视觉方向与主布局已由用户确认，首版已实现，实际验证见 [实现记录](implementation-status.md)。最后一轮未逐项回答的交互采用 [技术方案总纲](technical-plan.md) 中明确标注的工程默认值。

## 产品目标与范围

为本人提供 Eagle 式的网站收藏管理体验，直观浏览多个网站页面并整理大量链接。支持电脑和手机，首版仅联网使用，按一千个网站以内的规模设计与验收；离线缓存属于后续阶段。

前后端分离，后端可部署在本地或公开服务器。软件登录页面只要求密码，收藏对象仅覆盖无需登录即可访问的公开页面。

## 收藏与整理

- 管理网址、域名、网页名、文件夹、标签、备注及网站独立配置。
- 支持多级文件夹，每条收藏最多归属一个文件夹。
- 相同 URL 全库只保留一条收藏，重复添加时定位已有记录。
- 支持 Chrome 与 Firefox 书签导入，重复网站跳过，保留已有记录、配置和快照历史。
- 自有数据模型保存刷新间隔等软件配置，不受浏览器书签格式限制。
- 删除文件夹时删除其子树和收藏，同时删除相关快照历史；删除单条收藏也删除相关历史。
- 首版支持多选收藏后批量移动文件夹、增加/移除标签、删除收藏。
- 收藏星标为独立按钮：点击点亮表示页面已被收藏，不导航；再次点击取消星标，保留网站记录、文件夹归属及快照历史。点击卡片主体只选中，详情在当前界面展开。
- 软件调用 AI API 判断网页分类、规划文件夹，先生成待确认方案，展示网页、目标文件夹及待创建目录；允许人工修改，确认后才创建目录并执行归类。待确认的新网页暂放“未分类”。已进行的分类可以再次人工调整或重新生成 AI 方案，仍在确认后执行。
- AI 设置支持接口地址、API 密钥和模型名称，不固定供应商。分类输入采用网址、标题、简介及有限正文片段，不默认发送整个 HTML 快照；优先复用既有文件夹，必要时提出新目录。导入浏览器书签也可生成 AI 新分类建议，原目录路径保留作为人工校对参照，确认前不执行新归类。触发和校对细节见 [AI 分类方案](ai-classification.md)。
- 一千条为设计与验收范围，不设硬性容量上限；超出时提示，不自动截断导入，不承诺超范围性能。

## 备份与恢复

首版支持整库备份与恢复，包含收藏、文件夹、标签、备注、配置及全部桌面/手机快照历史。恢复覆盖当前库，使其回到所选备份状态；恢复前备份当前库。具体文件格式、一致性校验和恢复期间任务处理由实施方案确定，见 [备份与恢复](backup-restore.md)。

## 搜索

默认综合搜索，只列出相关网站收藏。采用部分匹配，列出所有命中的项；不要求全部关键词同时命中。

搜索框左侧提供名称为“搜索方式”的下拉框，弹出复选框列表，选择参与匹配的字段：域名、网址、网页名、标签、文件夹、备注。标签或文件夹匹配后返回对应网站，不单列标签或文件夹实体。首版不建立网页正文全文索引。

默认搜索全库，另提供范围切换，可限定当前文件夹及其子文件夹。多选标签按任一命中筛选；默认最近添加优先，另可按快照更新时间排序。快照更新时间使用当前展示设备版本的最近成功时间。

## 快照与预览

- 使用 Monolith 保存 HTML 网页快照，不使用 PNG 作为快照存储形式。
- 首版必须支持动态网页，目标与直接在浏览器中看到的页面一致。先经 Playwright/Chromium 渲染，再由 Monolith 归档。
- 每个启用快照的网站分别保存桌面和手机版快照，按访问设备显示对应版本。
- 收藏网格展示快照首屏，同时预览多个页面；首版不提供卡片大小调节。点击卡片主体选中并在当前界面展开详情，通过独立按钮打开原网站；收藏星标动作不导航。
- 当前分页全部可用页面预览自动进入加载队列，可限并发；已加载文档在上下滚动、翻页、切换收藏文件夹和应用内导航返回后保留，刷新整个网页后允许重载。不预加载未访问分页；详见 [ADR-0009](adr/0009-preview-document-retention.md)。
- 新快照追加历史版本，不覆盖旧版本。历史默认全部保留，提供手动清理，不按数量或时间自动淘汰。
- 支持多选清理旧历史，普通历史清理保留桌面和手机各自的最新成功版本；删除收藏或文件夹时仍删除全部相关历史，操作前显示受影响数量。
- 关闭快照功能时停止生成新版本，保留现有快照与历史，仍可查看。

| 状态 | 自动刷新 | 手动/文件夹刷新 | 已有快照与历史 |
| --- | --- | --- | --- |
| 快照开启、正常调度 | 按周期更新 | 可以 | 保留并追加版本 |
| 快照开启、暂停自动刷新 | 停止 | 可以 | 保留并追加手动版本 |
| 快照功能关闭 | 停止 | 跳过该网站 | 完整保留并可查看 |

尚无任何成功快照的网站仍可管理、搜索和打开原网址，卡片展示收藏信息及状态。

## 刷新规则

- 默认每周刷新一次，每个网站可单独配置刷新间隔。
- 新增或导入网站后立即在后台生成快照；关闭快照的网站除外。
- 支持按文件夹批量立即刷新，包含所有子文件夹，操作前显示待处理数量。
- 后台执行并显示进度。失败时保留最近成功快照及历史，标记失败。
- 后端重启时补刷已到期网站一次，不重放停机期间每个错过的周期。
- 桌面/手机快照分别记录成功时间与失败状态。

## 轻量技术方案

| 部分 | 已选技术 |
| --- | --- |
| 前端 | Preact、TypeScript、Vite、标准 CSS/CSS Modules |
| 后端 | Python 3.13、Django 5.2 LTS 原生 JSON views |
| 密码认证 | Django auth/session、django-axes，固定内部 owner |
| 数据 | 同机两份 SQLite：运行身份/会话/凭据与可恢复业务库隔离；HTML 文件保存快照 |
| 刷新执行 | 一个低并发 Django management command worker |
| 浏览器归档 | Playwright Python、Chromium、Monolith CLI |
| AI 与资源预处理 | HTTPX 通用协议适配、html5lib HTML 解析、tinycss2 CSS 解析 |
| 生产服务 | Waitress、WhiteNoise；快照经鉴权视图提供 |

前端构建为静态资源，卡片分页且按可见区域加载/卸载快照。浏览器按批次启动、复用、低并发采集并在空闲释放。所有收藏、任务、快照和历史接口验证所有者会话。

## 实施与验收边界

需求确认不代表已实现或测试通过。动态网页的 HTML 序列化不能自动证明浏览器视觉状态完整；需要真实网站验证首屏内容、样式、字体、嵌入内容、桌面/手机差异，以及 canvas、视频、shadow DOM 等边界，不能擅自降低用户的一致性目标。

还需验证导入兼容、单密码登录与访问控制、快照历史与手动清理、删除关联处理、任务恢复、手机多页面内存及首版规模。具体参数、URL 规范化和错误处理等技术默认值由实现方案明确；不将未测结果描述为已确认能力。

## 前端美术与界面方案

采用用户提供的[布局参考图](../doc/frontend-layout-reference.png)：电脑三栏、手机双列。应用使用灰白背景、深色文字，少量蓝色用于选中状态与主要操作；细边框、小圆角、轻阴影建立层次，控件规整对齐、适中留白、图标统一。网页预览作为主要视觉内容，应用外框保持克制，让网站自身的颜色自然呈现。

已确认方向、参考图和待细化的颜色值、字体、尺寸、状态与交互记录在[前端视觉设计方案](frontend-visual-design.md)。
