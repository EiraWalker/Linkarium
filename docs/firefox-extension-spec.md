# Firefox 一键收藏插件与后台 AI 自动归档规格

日期：2026-10-20。状态：已根据本轮对话整理，待实现与验收。本规格取代此前讨论的 Firefox 书签库同步方案。

用户已确认：首版只支持 Firefox；点击插件按钮提交当前页面的网址和标题；Linkarium 后台获取页面信息、执行 AI 分类并直接归档，无需人工确认。其余细节为本规格选定的工程默认，不视为用户逐项确认过的选项。

## Problem Statement

用户浏览网页时，希望立即将当前页面保存到自己的 Linkarium 收藏库，并让 AI 自动整理到合适的收藏文件夹。现有浏览器导入需要导出和选择书签 HTML，不适合随浏览随收藏；网页新增收藏也需要切换页面、输入链接，并人工确认 AI 分类方案。

现有新增收藏接口能够启动后台元数据、快照和 AI 任务，但 AI 结果只生成待校对方案，不会自动归档。浏览器插件与云端实例的认证、提交幂等性和最终分类状态也没有完整的接入契约。

## Solution

提供一个 Firefox 桌面插件，服务地址固定为 `https://link.eirawav.me`。用户在首次需要时完成 Linkarium 网页登录，之后点击浏览器工具栏上的「收藏到 Linkarium」按钮，即提交点击时所在页面的网址和标题，无需选择文件或再次确认。

服务端先可靠保存网站收藏，再在后台获取页面信息、生成 AI 分类方案并自动执行有效方案。用户提交后可以继续浏览或关闭来源页面；服务端接受请求后，分类不依赖 Firefox 继续运行。插件明确区分「已保存，正在分类」「已自动归档」「已存在」和「已保存，分类需要处理」。

自动归档仅适用于本入口新建的收藏及其对应任务，不把全站既有的分类校对流程改为自动确认。已有收藏再次提交时返回原记录，保留人工整理结果，不重新分类。

## User Stories

1. 作为 Firefox 用户，我希望通过工具栏按钮收藏当前页面，以便不离开正在浏览的内容。
2. 作为 Firefox 用户，我希望一次点击即可提交，以便不再选择书签文件或确认导入批次。
3. 作为 Firefox 用户，我希望保存的是点击瞬间的页面，以便切换标签页不会收藏错误的网址。
4. 作为收藏库用户，我希望链接和页面标题一起保存，以便提交后能够辨认收藏内容。
5. 作为收藏库用户，我希望收藏进入 `link.eirawav.me`，以便电脑和其他设备查看同一份收藏库。
6. 作为收藏库用户，我希望首次通过现有网页认证登录，以便继续使用已经配置的 Passkey 或文件密钥。
7. 作为收藏库用户，我希望登录有效期间无需重复登录，以便连续收藏多个页面。
8. 作为收藏库用户，我希望会话失效时得到登录提示，以便知道链接尚未提交而非误以为已保存。
9. 作为收藏库用户，我希望重新登录后能够继续原来的提交，以便不会把登录页面误当作来源页面。
10. 作为收藏库用户，我希望看到服务器已接受并保存收藏，以便放心关闭来源页面。
11. 作为收藏库用户，我希望后台自动获取页面信息，以便无需复制正文或手工填写分类依据。
12. 作为收藏库用户，我希望 AI 自动选择合适的收藏文件夹，以便减少日常整理操作。
13. 作为收藏库用户，我希望分类结果有效时直接归档，以便不再逐条确认普通收藏的 AI 分类方案。
14. 作为收藏库用户，我希望 AI 优先复用现有分类体系，以便目录不会随每次收藏不断碎片化。
15. 作为收藏库用户，我希望归档完成后能查看目标目录和收藏详情，以便核对实际结果。
16. 作为收藏库用户，我希望网络重试不会创建重复收藏或重复 AI 任务，以便重复点击仍然可靠。
17. 作为收藏库用户，我希望已存在的网址返回原收藏，以便保持原来的目录、标签、备注和历史。
18. 作为收藏库用户，我希望重复收藏不触发自动重分类，以便保留已经整理好的内容。
19. 作为收藏库用户，我希望 AI 未配置、不可用或返回无效结果时仍保留收藏，以便分类故障不会丢失链接。
20. 作为收藏库用户，我希望抓取正文失败时仍能用网址和标题尝试分类，以便受限页面仍有基本收藏价值。
21. 作为收藏库用户，我希望插件清楚显示尚未完成分类，以便不会把排队或失败误认为已经归档。
22. 作为收藏库用户，我希望分类失败后能够查看原因并重试，以便不用删除收藏再重新添加。
23. 作为收藏库用户，我希望后台任务在页面关闭和 worker 重启后恢复，以便不需要一直守着浏览器。
24. 作为收藏库用户，我希望手工调整目录后不会被迟到的 AI 结果覆盖，以便自己的整理始终有效。
25. 作为收藏库用户，我希望已有网页新增、浏览器 HTML 导入和手动重分类继续提供分类校对，以便本次自动归档只影响我明确使用的新入口。
26. 作为 Firefox 用户，我希望不支持的网址得到明确提示，以便知道本地文件或浏览器内部页面为何无法提交。
27. 作为 Firefox 用户，我希望插件只在主动点击时读取当前页的网址和标题，以便无需授予整个书签库或浏览历史的读取权限。
28. 作为收藏库用户，我希望插件不上传第三方站点的登录信息或页面正文，以便页面采集仍由 Linkarium 后台承担。
29. 作为收藏库用户，我希望看到实际安装和登录操作说明，以便能够在 Firefox 中使用插件，而不只是拿到源码。

## Implementation Decisions

### 入口和权限

- 首版交付 Firefox 桌面 WebExtension，采用 Manifest V3。工具栏按钮直接捕获当前标签页的 URL 和标题；成功提交不增加确认弹窗。辅助状态界面可以提供查看收藏、打开后台任务和重试入口。
- 目标实例固定为 `https://link.eirawav.me`，不提供实例切换。开发验收可使用单独测试构建连接隔离实例，发布构建不包含任意服务器配置入口。
- 使用 `activeTab` 读取用户点击所授权的当前标签页；使用本地存储保留未决提交标识；站点权限和固定内容脚本范围仅为目标 Linkarium HTTPS 域名。不申请书签、历史、全部站点内容、Cookie 读取权限，不向来源页面注入正文采集脚本。
- 只接受符合现有后端 URL 规则的 HTTP/HTTPS 页面。浏览器内部页面、扩展页面、文件和执行型 URL 在提交前拒绝；服务端仍执行自己的 URL 及采集目标校验。页面标题按现有字段限制校验，空标题可回退到网址。
- 点击时先保存来源 URL、标题和提交键，再进行任何登录跳转或标签页切换。后台脚本可能卸载，不依赖常驻内存保留提交状态。

### 认证与浏览器通信

- 复用现有 owner 网页会话、Passkey／文件密钥登录以及 CSRF 验证，不增加插件专用密码、长期 Token 或全站 CORS 放行。
- 工程默认采用目标站点内的同源会话桥：优先复用已打开的 Linkarium 普通窗口标签页；没有时创建后台标签页。扩展后台通过 Firefox 内部消息与固定内容脚本通信，由该脚本在 Linkarium 页面上下文中请求相对 API 地址。
- 内容脚本先读取 `GET /api/v1/session`，取得当前认证状态及 masked CSRF token；写请求同源携带会话及 `X-CSRFToken`。不读取或复制 HttpOnly Cookie，不在扩展中保存网站密码、私钥或 AI 密钥。
- 消息只接受本扩展的内部通信，限定固定操作及 API 路径，校验消息字段和目标标签页来源；不提供页面 `postMessage` 可调用的任意请求代理，不动态执行页面提供的脚本。
- 未登录时显示「请先登录 Linkarium」，将 Linkarium 登录页置前；待用户完成现有认证后继续保存的原提交。同一 Firefox 普通浏览上下文复用对应会话，首版不支持隐私窗口和容器标签页。
- 网络失败、会话过期、CSRF 失效和维护状态分别反馈。CSRF 更新可以有界重试；401 必须完成登录，不通过关闭认证检查继续提交。是否已保存不明确时使用原提交键恢复结果。
- 同源桥只是短暂的认证与 HTTP 传输通道；服务端接受提交后，即使桥标签页被关闭，后台分类仍继续。Firefox 真实环境中的 Cookie、CSRF 与消息行为是必须验收的交付条件。

### 提交 API 与去重

- 新增专用入口 `POST /api/v1/extension/submissions`，请求体仅含 `url`、`title`，必须有 owner 会话、CSRF 和 `Idempotency-Key`。客户端不传目录决策、AI 原始 JSON、任意执行策略或供应商凭据。
- 新提交返回 `202`，统一响应信封的 `data` 包含 `submission_id`、`bookmark_id`、`created`、`state`、`stage`、`group_id` 及受控的后续状态地址。异步响应只代表已保存并登记工作，不代表已完成分类。`group_id` 在尚未生成子任务时允许为空。
- 规范化 URL 已存在时返回 `200`、`created=false`、`state=already_saved` 及原收藏标识；不覆盖标题、目录、标签、备注、星标、刷新设置或快照，不自动触发重分类或新的初始抓取。
- 复用现有 URL 规范化和收藏创建领域规则。同一提交键同参重试返回原提交和原创建结论；同键异参返回现有幂等冲突错误。不同提交键并发保存相同 URL 仍只能创建一个收藏及一套初始工作。
- 新记录保存来源标题，初始归属「未分类」，标记收藏星标。快照开关和刷新行为沿用现有新增收藏的默认，不新增插件采集偏好。
- 收藏、提交工作流、幂等响应与待执行工作应在业务库同一事务中登记，避免响应成功后重启丢失分类任务。复用领域创建逻辑，但避免原初始流程与插件流程各排一套重复 AI 任务。
- 新增 `GET /api/v1/extension/submissions/{id}` 查询保存结果、收藏标识、阶段、任务组、分类结果、目标目录及可读错误。只在当前已认证收藏库中可查询，不返回凭据或完整供应商响应。
- 新增 `POST /api/v1/extension/submissions/{id}/retry` 重试同一提交的失败阶段，校验 owner、CSRF、幂等键及当前版本；复用活动任务，不重新创建收藏。自动归档因人工修改失效时不以重试强行覆盖，转入现有人工处理入口。
- 不依赖尚未实现的本机管理 API／CLI，也不把本功能扩展为其远程实现。

### 后台分类与自动归档

- 复用现有 worker、任务批次、元数据采集、AIProfile 验证、共享分类体系、AI 分类方案校验和目录归属领域操作，不建立第二套分类引擎。
- 为插件新提交持久记录来源、自动应用策略、库身份、收藏分类版本、关联任务和最终执行结果；这些是业务状态，放入业务库。登录会话和供应商凭据继续留在运行库，不引入跨库外键。
- 工作顺序为保存记录、获取有界元数据、生成方案、校验并自动应用。元数据成功或在有界重试后失败，均可推进到分类；失败时使用已保存的网址和标题并记录信息不足。快照任务按既有设置独立运行，不因另一设备快照失败永久阻塞分类。
- AI 必须使用当前已配置且验证有效的活动 AIProfile。没有有效配置时收藏仍保存，分类进入需要处理状态；不编造成功方案、不改用未经验证的服务，也不弹出插件内 AI 配置向导。
- AI 复用现有目录和共享分类范围，继续遵守输出结构、目录层级与数量预算。合法方案可按现有规则创建缺失目录；目录创建、收藏移动、方案应用状态及工作流终态应在同一业务事务完成。
- 自动应用复用现有分类确认领域校验，不在 worker 中绕过规则直接设置任意目录。记录为插件策略自动应用，能够区别于人工确认；合法完成后不留一个仍待确认的同一方案。
- 全站缺省仍为人工分类校对。只有本入口新建记录所对应的持久策略可以自动应用；网页新增、HTML 导入、既有收藏和手动重分类不继承该策略。
- 晚到的 AI 响应必须核验任务仍有效、库 epoch、收藏分类版本和目录版本。用户已手动移动收藏、发起替代分类，或库已切换时，不覆盖新状态。目录变化按现有方案失效规则转为需要处理，保留收藏及可说明的原因，不盲目重基执行旧方案。
- 网络和供应商瞬时故障沿用现有有界重试、任务去重和租约恢复。无效输出、未配置 AI 或重试耗尽时保留已保存记录；自动归档未完成不得标记为成功。

### 状态和后续操作

- 提交状态与底层 Job 状态分开：工作流可为 `queued`、`enriching`、`classifying`、`applying`、`classified`、`needs_attention`、`already_saved`；底层排队、运行、等待重试及失败仍沿用现有任务语义。
- 插件收到可靠接受响应后立即显示「已保存，正在分类」，不会等待 AI 完成才返回。能够取得终态时显示「已自动归档」及目录；`already_saved` 显示「已存在」；分类受阻显示「已保存，分类需要处理」及打开后台任务／收藏的操作。
- 网络断开且未取得可靠结果时显示「提交结果待确认」，不可宣称已保存或已归档；重新连接后以原键有界恢复。首版不提供离线收藏队列和跨会话批量补传。
- 插件状态读取不产生新的分类任务。服务端接受后不要求浏览器常驻轮询；Linkarium 现有后台任务入口能够恢复查询该流程和关联工作，插件再次打开也能读取保存的提交结果。
- 用户仍可在网页修改最终归属。自动归档是本次新建收藏的处理策略，不授予后续定时重分类覆盖手工修改的权利。

## Testing Decisions

- 测试以外部可观察行为为准：提交了什么页面、实际创建多少记录、最终目录是否正确、重复请求是否复用、故障是否保留收藏、会话是否被正确验证；不测试私有函数调用次数或逐行复刻实现。
- 主要测试边界是完整的「插件按钮 → 已认证提交 API → 真实 worker → 分类结果应用 → 收藏查询」。使用隔离收藏库、可控公开页面和现有确定性 AI 协议服务，替换外部供应商响应，保留真实的请求解析、持久化、队列、方案校验和目录事务。
- 优先扩展既有 HTTP 收藏／幂等集成测试、分类任务与方案确认测试、认证与 CSRF 测试，以及受控 AI 协议验收的准备设施。测试覆盖实际任务推进，而不是只断言返回 202。
- 最小成功验收：在真实 Firefox 中完成现有登录，浏览一个受控页面并点击按钮；核对服务端保存的来源 URL／标题、收藏星标、任务来源，等待后台完成后读取实际文件夹归属，确认无需人工确认且没有遗留的同一待校对方案。
- 同一页面重复点击、同键重试、响应丢失后恢复以及不同键并发提交，均只创建一个收藏和一套工作；已存在记录的人工字段及归属保持不变。
- 验证来源页面切换、登录页打开、Linkarium 桥标签页关闭、来源页面关闭以及 Firefox 后台脚本重新唤醒时，来源身份不混淆；服务端已接受的任务不被这些浏览器事件取消。
- 认证边界在真实 Firefox 验证：未登录引导、登录后续提、会话失效、CSRF 轮换、站点权限未授予。匿名和缺失 CSRF 写请求不能创建收藏或触发 AI。纯后端测试不替代此项浏览器验收。
- 验证 AI 未配置／未验证、供应商超时、无效方案、元数据抓取失败、worker 中断后恢复：收藏始终保留，终态和可重试状态如实展示；元数据失败仍可用 URL／标题分类。
- 验证自动应用前用户移动收藏、目录树变化、替代分类任务、库 epoch 变化及重复 worker 完成：旧结果不覆盖新状态，不重复创建目录，不重复移动。
- 回归网页新增、HTML 导入和手动重分类：仍只产生待校对方案，不自动归档。已有目录创建约束、AI 目录来源记录和空目录清理规则继续生效。
- 受控 AI 协议服务证明流程正确，不证明真实模型分类质量；真实供应商的单页验证及 Firefox 可安装包验收需在实现后另行记录。源码、构建成功或临时加载插件本身不能代替用户可用性验收。

## Out of Scope

- Firefox 书签库读取、书签文件导入改造、后台持续书签同步、书签删除或双向同步。
- Chrome／Edge／Safari、Firefox 移动端、隐私窗口和容器标签页。
- 任意实例地址配置、全新通用远程管理 API、CLI 和 Agent Skill。
- 插件上传正文、DOM、截图、选区、浏览历史、第三方站点 Cookie 或登录态；服务端代登录受限页面。
- 全站自动确认 AI 分类、对既有收藏自动重分类、批量自动整理和定时重分类。
- 离线收藏队列、跨设备同步插件配置、定制 AI 服务或模型配置界面。
