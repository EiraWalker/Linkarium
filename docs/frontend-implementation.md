# 前端实施方案

日期：2026-10-09。响应式界面已实现，实际点击与预览池验证见 [实现记录](implementation-status.md)；实体手机与跨浏览器测试仍待执行。

本方案依据[需求规格](requirements.md)、[视觉方案](frontend-visual-design.md)和用户提供的[原始参考图](../doc/frontend-layout-reference.png)。参考图已人工查看。用户确认的灰白背景、深色文字、少量蓝色、电脑三栏、手机双列与首版不调节卡片大小是约束；本文的尺寸、色值、断点、路由和操作默认值是本次委托规划的可调整实施基准，不冒充逐项得到过用户确认。

## 1. 范围与实现结构

采用 Preact、TypeScript、Vite 和 CSS Modules。全局设计变量放在标准 CSS 中，功能样式按组件局部组织。使用 Preact 原生 hooks/context、内置 createPortal、小型 API 请求封装和浏览器 History API，不增加 Redux、React 运行时、完整 UI 组件库或路由库。createPortal 由现有 Preact 包的 compat 入口导出，仅用于将列表内容放入稳定滚动容器，不增加依赖或引入 React 组件。

建议文件职责：

```text
frontend/src/
  app/                 应用启动、会话、路由、错误边界、页面壳
  api/                 请求、CSRF、错误转换、类型与取消请求
  styles/              tokens、基础样式、焦点与响应式规则
  components/          Button、Dialog、Drawer、Field、Icon、Status
  features/library/    导航树、搜索、筛选、卡片、选择与详情
  features/previews/   iframe 挂载调度、尺寸计算和预览状态
  features/classify/   AI 分类方案校对与提交
  features/history/    历史选择、预览与清理
  features/transfers/  导入、备份、恢复及任务进度
  features/settings/   刷新设置、AI 设置与退出登录
```

这是一份建议结构，不表示文件已创建。共享组件只提取跨页面真实复用的部分，避免为首版建立复杂组件平台。API 类型随统一 `/api/v1` 契约维护；响应在请求边界检查必要字段，不把 TypeScript 类型断言当成运行时验证。

Preact 的 `useReducer`、`useContext` 和带清理函数的 `useEffect` 已经能覆盖此处的状态与订阅需求；实现直接从 `preact/hooks` 导入。官方资料支持该使用方式，不需要为了状态管理引入兼容层。[Preact Hooks](https://preactjs.com/guide/v11/hooks/)

## 3. 响应式布局

| 可用宽度 | 导航 | 中央内容 | 详情 |
| --- | --- | --- | --- |
| ≥1200px | 左栏 224px | 自适应网格，卡片最小约 224px，间距 16px | 右栏 320px；可关闭，再次选择卡片打开 |
| 768–1199px | 左栏 208px，可收起 | 至少保留可浏览内容宽度；按可用空间排列 | 右侧覆盖式详情抽屉，宽度最多 360px |
| ≤767px | 顶部按钮打开文件夹/标签抽屉 | 固定双列，间距 10px；页面边距 12px | 当前页面底部详情弹层 |

≥1200px 时默认保持三栏；未选网站时右栏显示简短的选择提示。桌面右栏首版固定宽度，提供关闭入口，不提供拖动调宽。卡片首版没有尺寸滑杆、密度档位或手机单列切换；列数变化只来自屏幕宽度。

桌面中央信息顺序：文件夹标题与数量 → 刷新文件夹/添加网站 → 搜索方式与搜索框 → 搜索范围、标签、排序 → 批量操作条（选择后出现）→ 卡片与分页。手机保留同一语义，工具行可换行；次要动作进入有文字的更多菜单，避免挤压搜索输入。

手机详情弹层是实施默认：初始占约 72dvh，可通过明确的展开按钮扩展到接近全屏；拖动手柄是可选增强，不成为使用前提。内层滚动，底部保留安全区域，关闭后恢复原卡片焦点及网格滚动位置。软键盘弹出时保持输入与保存按钮可达。首版不进入独立收藏详情页面。

每个可滚动区域有明确滚动所有权：桌面导航、网格、详情可各自滚动；手机主体采用页面滚动，打开模态抽屉/弹层后锁定背景。禁止弹层滚到边缘时连带滚动背景。

## 4. 首屏预览与参考图的取舍

采集初始配置与后端一致：桌面 1366×768 CSS px，手机 390×844 CSS px。每条 `SnapshotSummary` 必须返回实际 `viewport_width`、`viewport_height`、`variant`、`captured_at`、`preview_url` 和 `status`；前端以记录值为准，旧版本不随新采集配置重新解释。

为了接近参考图的规整卡片，卡片预览框初始采用桌面 4:3、手机 1:1。iframe 内部视口始终保持采集时的宽高，按卡片框宽等比缩放，居中靠上显示：

```text
scale = previewContainerWidth / snapshot.viewport_width
iframe 的 CSS width = snapshot.viewport_width
iframe 的 CSS height = snapshot.viewport_height
iframe transform = scale(scale)，transform-origin = top left
外部容器 = 固定比例、overflow:hidden
```

当手机完整首屏比正方形框更高，卡片只显示首屏顶部，完整首屏可在详情中按原始比例查看、随外层面板滚动。桌面缩放后如比容器矮，下方留浅色空白，不拉伸。**这是卡片展示裁剪，不裁剪归档文件，也不将手机页面改成桌面快照。**该取舍需要在视觉样例中明确展示，卡片比例允许据真实快照辨识效果调整，不追加用户尺寸调节功能。

iframe 外部缩放不得改成把其布局宽度设成卡片宽度，否则会让网页重新触发窄屏布局。不得把快照 HTML 拼进应用 DOM，也不以生成 PNG 缩略图解决排版或性能问题。详情的桌面/手机选项显式选择对应历史，缺失版本展示缺失状态，不静默替换成另一设备版本。

全局 `device=desktop|mobile` 决定网格快照类型和按快照时间排序所用版本。初访默认在 ≤767px 时选 mobile，否则 desktop；用户明确切换后记录在 URL 和界面设置中，宽度变化不再覆盖此选择。详情可以临时比较另一设备快照，不自动改变网格卡片尺寸或当前排序。

## 5. HTML iframe 的权限与资源管理

### 5.1 私有预览

- 使用服务器鉴权后的同站点预览地址作为 iframe `src`，源站不是被收藏网站，不直接嵌入实时网页。
- iframe 使用空 `sandbox` 限制集，不添加 `allow-scripts`、`allow-same-origin`、表单、弹窗、下载或顶部导航能力；响应还必须有后端定义的 CSP 和内容类型防嗅探策略。前端属性与后端响应是两层约束。
- 卡片预览使用 `pointer-events:none`、`tabIndex=-1`，预览区域由应用自己的选择按钮承接点击。原网站通过独立的 HTTP/HTTPS 链接打开，并隔离 `opener`。
- 预览仅承担视觉识别，卡片文本提供标题、域名、时间及状态；不要求辅助技术进入数十个静态页面。详情也提供应用自己的文本说明和“打开原网站”入口。
- 预览请求失败时不得显示软件登录页嵌套在卡片内。私有快照鉴权失败返回明确失败响应；会话状态由 API 请求统一判断和处理。
- iframe `load` 事件不等同于 HTTP 成功或内容完整。UI 的“快照成功”来自后端记录，加载超时只标记“预览未加载”，不能覆盖采集结果。[MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)

沙箱与 CSP 对外链、内嵌页面和动态内容的影响在归档 PoC 中验证；不得为了让某个快照显示正常而在前端开放任意脚本或同源权限。后端提供适合受限查看的归档内容，视觉缺陷按实际能力报告。

### 5.2 加载调度与文档保留

2026-10-15 起采用 [ADR-0009](adr/0009-preview-document-retention.md)。加载并发与文档保留分开管理：当前分页全部快照入队，完成的文档保留到本次应用运行结束或对应数据失效。

1. 列表默认每页 48 条，服务器单页上限 100 条。当前分页元数据就绪后，该页所有可用快照进入队列，不要求滚动触发，不预加载未访问分页。
2. 加载优先级为详情／历史、可见卡片、本页其余卡片；无滚动事件时队列也会完成整页。桌面并发 2、手机并发 1，失败和超时释放额度。
3. 已加载文档由应用运行期的共享模块持有；列表和详情滚动容器也保留到会话结束。预览使用容器内容坐标绝对定位，原生滚动同时带动卡片与预览，原生 overflow 完成裁剪；滚动时无需逐帧用 JS 更新坐标。列表和表单通过 Preact 自带 portal 挂入稳定容器，离开后卸载这些临时内容、隐藏容器，保留文档不移动父节点。
4. 上下滚动、翻页、切换收藏文件夹、应用内导航及标签页隐藏均不淘汰已完成文档。离开旧页时取消尚未开始的工作，已开始的请求可以继续完成。
5. 同一快照在同一滚动区域的不同列表间复用；桌面／手机与不同历史版本分别识别。卡片与详情属于不同稳定滚动区域，允许独立文档，后续复用各自区域内的空闲文档。
6. 退出登录、会话失效或收藏库身份变化销毁预览会话；删除收藏或历史时释放对应文档。新版本与旧版本不混用。刷新整个网页后允许重载，不增加跨刷新持久化。
7. 既有鉴权预览资源支持 HEAD 检查状态与 HTML 类型，再由 iframe GET 加载；保持空 sandbox、CSP 和 no-store。load 事件不代表后端采集成功。

内存会随本次运行访问过的不同快照数量增长。浏览器夹具可证明保留和队列行为，实际归档体积、内存曲线和实体手机表现仍需对应证据；本次不设会让已完成预览丢失的自动淘汰规则。

## 6. 页面、路由与浏览状态

使用固定路径匹配函数加 History API 管理少量路由。点击内部链接时只拦截同源、无修饰键的普通主按钮点击；新标签页、中键与浏览器前进后退保留原生行为。监听 `popstate` 并恢复路由状态。后端只为已知前端路径返回应用入口，`/api/v1`、快照地址及不存在的资源不回退到 SPA HTML。

| 页面 / 路由 | 职责与展示 |
| --- | --- |
| `/login` | 单密码登录；密码显示切换、提交中、错误和临时限流状态 |
| `/library` | 网站网格、导航、搜索、批量整理、当前详情 |
| `/classification` | 分类任务、建议校对、修改、批量确认及驳回 |
| `/settings` | 默认刷新设置、AI 连接配置与账号退出 |
| `/transfers` | 浏览器导入、整库备份/恢复、传输与任务进度 |

库页面 URL 参数承载可复现查询，例如 `folder`、`q`、`fields`、`scope`、`tags`、`sort`、`device`、`page`、`selected` 和 `panel=history`。实际参数名与 API 映射集中在一个模块。卡片选中和打开历史都保持库页面上下文，不生成独立收藏详情路由。

其中界面参数 `device` 映射为 API 的 `variant`，取值均为 `desktop` 或 `mobile`；快照尺寸读取响应中的 `viewport_width`、`viewport_height`，不另造一套服务端字段。

输入搜索时 250ms 防抖并 `replaceState`，避免每个字符创建浏览历史；切换文件夹/分页/主页面使用 `pushState`。弹层打开可创建一条同路由历史记录，使手机返回键先关闭弹层；从直接链接打开时，关闭采用移除参数而非盲目后退到站外。

滚动位置、展开的文件夹节点和未提交短期编辑保存于当前页面内存/`history.state`。首版不把完整收藏库、快照或 API 密钥写入 `localStorage`。长期界面偏好仅保存非敏感的已选设备等少量值，不将此称为离线能力。

## 7. 状态、请求和并发编辑

分离四类状态，避免一个全局对象导致整个网格重绘：

| 状态 | 管理方式 |
| --- | --- |
| 会话、库版本、维护状态 | 小型 context，共享给受保护页面 |
| 路由、查询和当前选中 ID | URL + 页面 reducer |
| 服务端列表、详情、任务 | 各功能请求 hook；按查询键去重、过期重取 |
| 弹层、表单草稿、多选 ID、预览槽位 | 局部 reducer；预览槽位由唯一管理器持有 |

统一请求封装使用相对 `/api/v1` 地址和同源会话 cookie。启动时通过 `GET /api/v1/session` 取得会话状态与 masked `csrf_token`，修改请求把该值放入规定的 CSRF 请求头；登录后重新取得 token，避免沿用轮换前的值。密钥与登录凭据不放在 URL。搜索切换通过 `AbortController` 取消前一请求，同时检查请求序号，防止迟到结果覆盖新查询。effects 清理事件监听、observer、计时器与请求。

API 错误按统一 `error.code`、`message`、`fields`、`request_id` 等契约映射，不直接向用户显示堆栈。处理规则：

- 401：清除受保护数据显示并回到密码登录，登录后恢复允许的站内位置。
- 403/CSRF：提示会话或校验已失效，重新取得会话状态；不自动反复重放写请求。
- 409/revision 冲突：保留当前草稿，显示服务端最新值，允许重新读取后再提交；不得静默覆盖另一台设备的修改。
- 429：显示可重试时间，遵循响应约定，不持续轮询撞限流。
- 验证错误：定位相应字段；任务失败展示明确阶段与重试入口。
- 网络异常：保留当前可见数据并标记连接中断；写入结果不明时查询状态，不直接假定失败后再次执行。
- 恢复维护中：切换为全局维护提示，禁止普通写操作。停止 Web 服务维护期间可能断连或收到 502/503，这只说明暂时无法取得状态，不代表恢复失败；待服务恢复后继续查询原操作进度。

写请求附资源 `revision`，成功后以服务端返回的实体及新 revision 为准。星标可做单项乐观显示，但同一条记录串行写入，失败回滚到最后确认状态；其请求是“设为 true/false”，不能采用易重复翻转的 toggle 命令。备注、刷新间隔和 AI 设置有明确保存动作，未保存草稿在关闭时提示。

批量移动、标签、删除及分类确认使用后端规定的批次/幂等标识。前端不把复杂原子操作拆成数十次单条请求自行拼装，失败也不制造“全部成功”的提示。完成任务后只刷新相关查询；保留仍存在的选择，移除被删除或移出结果的 ID。

## 8. 各流程的具体交互

### 8.1 登录与应用启动

登录页居中显示产品名、密码框和主按钮，不出现用户名/邮箱/注册字段。密码错误使用统一文案；限流显示等待时间。首次启动先请求会话与库状态，未确认身份前不渲染库元数据。退出后清除页面缓存、预览和表单中的秘密字段。

### 8.2 库、星标、搜索与批量整理

卡片包含首屏预览、标题、域名、星标、独立原站入口及状态。桌面优先显示少量标签，过多显示数量；手机优先显示标题、域名和当前设备快照时间。长标题最多两行，完整内容可在详情阅读。

星标与多选复选框分离：星标修改“收藏标记”，复选框加入批量操作。星标、外链、更多按钮点击不冒泡为卡片选中。**新建/导入默认不点亮星标，并提供“全部网站”和“星标收藏”筛选，作为本次规划默认。**已有分类可以人工调整，也可以主动重新请求 AI 建议。

“搜索方式”文字固定在输入框左侧，打开原生复选框组成的浮层，至少选择一个字段。默认搜索全库，界面明确标注当前范围；选择“当前文件夹及子文件夹”后发送对应范围。标签为任一命中，标签过滤和关键词结果共同约束列表。默认最近添加排序；快照更新时间排序使用当前 `device` 最近成功时间，无快照项排在有时间项后，稳定次排序由 API 规定。

切换查询时清空跨查询多选，避免看不到的项目被操作。首版“全选”明确表示当前页，不伪装为全库选择；每条可见卡片始终可以勾选，手机通过“多选”进入选择模式。批量移动选一个目标文件夹，增减标签明确选择添加或移除，删除先展示服务端计算的影响数量。

空库提供添加/导入入口；空搜索提示修改关键词/范围；未分类为空不显示错误。首次加载用与卡片尺寸一致的骨架，局部刷新保留旧卡片并标记加载，避免列表闪空。

### 8.3 刷新和快照状态

刷新文件夹包含子文件夹，执行前显示符合条件的数量及快照关闭的跳过数量。任务开始后返回任务 ID；固定进度区域展示已完成/总数、失败、跳过和当前阶段，可展开详细记录。低并发 worker 不影响页面继续整理。

任务活动期间初始每 2 秒轮询，隐藏标签页降至 15 秒，完成后停止；网络错误退避，上述值属于可调实现参数。已有成功快照时刷新失败仍显示该版本，同时展示最后成功时间和本次失败；不得以骨架覆盖可用内容。桌面与手机版分别显示状态，整体部分成功可展开查看。

尚无快照、等待采集、正在生成、生成失败、快照关闭、自动刷新暂停分别使用准确文字。快照关闭仍能查看旧版本；暂停自动刷新仍允许手动任务，UI 与后端语义一致。

### 8.4 AI 分类校对

新增网页自动生成建议，已有网站或文件夹由用户主动发起重分类，定时快照刷新不附带自动重分类，以上是规划默认。待确认的新网页保持未分类；已有网站在确认前维持原归属。

校对页逐条显示网站、原路径参照、当前目录、建议目标、待创建路径和建议状态。人工可选择已有目标或编辑新路径；新目录有明确标识。支持勾选多条确认或驳回。确认成功才更新库导航树和网页归属；驳回保留网站及其当前分类。

AI 未配置、连接失败、部分网页失败和返回无效建议时，页面保持可人工管理；不阻止导入完成、快照刷新或浏览。过期方案、目录重命名/删除与 revision 冲突显示受影响行，保持人工修改内容供重新选择，不能自动重建已删除目录后直接提交。

### 8.5 详情、历史与清理

详情按参考图展示标题/域名、桌面与手机快照、原站入口、标签、备注、归属、刷新间隔、快照开关和历史摘要。历史列表按设备切换，显示成功时间、最新标记和状态；点旧版本仅更换详情预览，不把它设为当前最新成功版本。

多选清理时，桌面和手机各自最新成功版本不可选；界面说明保留原因。提交前显示选中版本数，空间回收量只有后端能给出可靠值时才显示。清理失败保留失败项供重试。删除网站/文件夹另走级联删除确认，明确会删除相关历史，不借历史保护规则阻止已确认的整条删除。

### 8.6 导入、备份与覆盖恢复

导入流程为：选择浏览器 HTML → 上传/解析 → 显示新增、重复跳过、无效数量 → 确认导入 → 查看导入结果及分类校对入口。原书签路径作为校对信息，重复不覆盖既有记录。超出一千条显示规模提示，导入不自动截断。

备份与恢复使用 state 数据库中的 `MaintenanceOperation`，创建响应返回 `operation_id`，不存放在将被覆盖的 library job 中。备份页显示进行阶段、文件大小（可得时）、完成时间和受保护下载入口。不得用模拟百分比掩盖正在打包但不可量化的阶段。用户离开页面后后台操作持续，再进入通过维护操作记录恢复进度。

恢复流程为：上传 → 校验 → 展示备份内容摘要和覆盖影响 → 明确确认覆盖 → 自动备份当前库 → 执行恢复 → 刷新库状态。恢复失败显示系统仍处于哪个库状态及下一步，不让用户猜测。覆盖确认与创建备份成功之前不显示“开始恢复成功”。恢复后丢弃列表/详情/预览缓存，重新拉取应用状态；服务端要求时重新登录。前端不控制文件替换，不把页面关闭当成取消恢复。

提交前产生并保留该次请求的 `Idempotency-Key`，收到响应后保留 `operation_id`。这两个不含密钥或库内容的恢复关联值可放入当前标签页的 `sessionStorage`，直到取得终态。若创建响应丢失，使用相同 key 重新取得原 `MaintenanceOperation`，不能生成新 key 再次发起覆盖。维护中断连、502/503 和登录失效都保留关联值；重新登录后通过 `operation_id` 查询完成状态。只有服务端返回操作终态，才显示成功或失败并清理关联值。

### 8.7 设置

刷新设置展示默认每周与网站独立配置的关系。AI 设置包含接口地址、模型、密钥输入和连接测试结果；已有密钥只显示是否配置，不回填明文。密钥由后端持有，不能放入 Vite 环境变量打包进浏览器。具体支持的协议与密钥备份范围遵循后端方案。

## 9. 键盘、触屏和可访问性

- 使用按钮、链接、input、checkbox 等原生元素；卡片采用独立“选中此网站”按钮和同级动作，避免按钮内再嵌按钮。
- Tab 能到达导航、搜索方式、输入、筛选、卡片选择、星标和外链。Space 切换复选框/星标，Enter 执行明确选中或打开按钮，Escape 关闭最上层浮层。
- 文件夹树用可展开按钮与嵌套列表表达层次，包含展开状态和当前项；不实现一半的 ARIA tree 键盘模型。
- 弹层设置标题、模态语义、焦点约束与焦点恢复；层叠弹窗尽量避免，危险确认一次只显示一个。
- 删除键不直接删除数据。批量选择提供明确按钮，操作不依赖右键、拖拽、悬停或长按。
- 触屏点击区域保持可达，底部弹层、进度条和系统安全区域不遮挡操作；缩放文字时允许换行。
- 任务进度以节制的 live region 通知阶段变化，不每轮轮询朗读全部状态。动画遵循减少动态效果偏好，加载占位不强制持续闪烁。

## 10. 构建与交付边界

开发时 Vite 只承担开发服务器与热更新，API 经同源开发代理转发。生产构建生成静态 HTML/CSS/JS，由既定 Django/WhiteNoise 入口提供；`vite preview` 仅用于本地检查，不作为生产服务器。需要后端模板引用带 hash 的文件时启用构建 manifest，并在构建流程中验证入口和资源路径匹配。[Vite 生产构建](https://vite.dev/guide/build)、[后端集成](https://vite.dev/guide/backend-integration)、[静态部署](https://vite.dev/guide/static-deploy)

前端构建产物与私有 HTML 快照目录分离。服务端运行不需要 Node 常驻；设置、AI 密钥、会话配置不进入前端构建产物。依赖安装时选择相互兼容的稳定版本并提交 lockfile，本文件不将文档主分支 API 等同于已锁定的发布版本。

按顺序交付：先做参考图布局与真实 iframe PoC → 库与搜索/详情 → 分类校对与任务进度 → 导入/历史/备份恢复 → 真机与跨设备验收。技术实现前先产出覆盖桌面和手机的视觉样例，采用实际归档展示卡片裁剪与详情比例。

## 11. 前端验收

以下是必须证明的行为，而不是只检查组件是否被调用：

| 场景 | 验收内容 |
| --- | --- |
| 桌面与手机布局 | 1440、1200、1024、768、390、360、320 CSS px 检查；电脑三栏、手机双列；长中文标题和深层目录不产生页面横向溢出；无大小滑杆 |
| 星标与详情 | 点星标不打开详情，取消保留数据；卡片主体只选中；外链独立；手机关闭弹层恢复滚动位置 |
| 查询正确性 | 搜索方式多选、字段部分匹配、全库/当前子树、标签 OR、排序设备一致；迟到响应不能覆盖新查询 |
| 跨设备修改 | 两台客户端编辑同一网站，旧 revision 不覆盖新值；错误时保留草稿并提供重新读取 |
| 快照展示 | iframe 内视口不随卡片缩窄；桌面/手机版本确实不同；卡片裁剪与详情完整首屏一致；不会展示 PNG 替代品 |
| 快照权限 | 无登录直接访问快照失败；归档脚本、弹窗和顶部跳转不能执行；快照无法读应用数据或会话；退出后界面预览全部释放 |
| 加载与保留 | 不滚动也完成当前分页；滚动、翻页和应用内导航后已完成文档不重载；重复访问相同快照不重复创建；记录首次访问不同页面时的资源增长 |
| 真实移动端 | 在实际手机 Chrome/Firefox 可用平台及 iOS Safari 检查缩放、弹层、软键盘与 HTML 内存压力；桌面移动模拟不能代替真机结论 |
| 状态真实性 | 无快照、部分成功、失败保留旧版、暂停、关闭分别正确；iframe load 不被当成抓取成功；失联不显示虚假完成 |
| 分类校对 | 修改/批量确认/驳回有效；确认前无新建文件夹和移动；过期建议冲突可处理；AI 故障不阻断普通管理 |
| 导入/恢复 | 重复跳过结果可读，过千不截断；恢复前展示覆盖范围，恢复维护中不可写；丢失创建响应后同 key 获得原 operation，断连/502/503 不误报失败；重新登录后查得原操作终态；完成后缓存清空且显示恢复后的库 |
| 键盘与触屏 | 无鼠标完成搜索、选择、编辑、关闭与确认；焦点不进入静态 iframe；抽屉/弹层焦点恢复；关键操作不依赖悬停 |

自动化优先覆盖状态转换、查询竞态、revision 冲突、预览加载队列、文档保留与失效，以及端到端关键流程；视觉与内存使用真实归档、真实浏览器检查。初始应用 JS gzip 预算建议控制在 150KiB 内（不含快照），预览稳定后再确定可测性能目标。打包体积通过并不能证明多 iframe 页面足够流畅。

对比参考图的验收重点是应用外框克制、内容对齐、选中状态和网页辨识度；示例图中的网站画面不构成动态归档保真证据。
