# 备份与恢复方案

2026-10-09。整库备份、恢复前备份、覆盖恢复与回退已实现，并完成真实 supervisor/API 和界面验收，见 [实现记录](implementation-status.md)。

## Eagle 官方资料核对

- 完整资源库备份/迁移：复制整个 `.library` 资源库，素材、分类、文件夹设置及标签一起保留，也可先压缩再传输。[Eagle 官方资源库技巧](https://cn.eagle.cool/blog/post/best-practice-for-eagle-library)
- `.eaglepack` 是素材或文件夹的导出分享包；多个资源库独立，合并是另一种操作。[Eagle 官方导入导出说明](https://cn.eagle.cool/blog/post/how-to-import-export-in-eagle)

这些官方正文发布于 2022 年，本次已重新读取。当前帮助中心的备份、恢复和合并页面仅取得标题与导航，未据此确认自动覆盖、默认合并或重复冲突规则。不能将“参考 Eagle”解释为全部功能或格式兼容。

## 已确认的产品行为

本软件提供整库备份，包含网站记录、文件夹、标签、备注、单站配置及桌面/手机 HTML 快照历史。具体文件格式属于实现设计，不直接使用 Eagle 格式。

技术规划选用带 manifest 的 ZIP64 包；可迁移业务配置随库备份，当前登录密码、会话、AI API 密钥和主机配置保存在运行库中，不随业务恢复回滚。操作由 state 中的 MaintenanceOperation 和维护控制器完成。文件格式、一致性、凭据绑定、恢复步骤及失败回退见 [运行与安全方案](operations-security.md)。

首版采用整库覆盖恢复：恢复前备份当前数据，校验备份完整性后，将当前库恢复到所选备份的状态。这是替换而非合并；不因参考 Eagle 而增加多库切换或素材包合并功能。

由实施设计备份期间的数据与文件一致性、恢复期间任务处理以及中断回退。不直接拷贝运行中的数据库和历史文件后就宣称完整备份成功。

## 备份临时空间

2026-10-18。备份维护窗口仍由 supervisor 停止 web、worker 和采集发布/清理进程，完成归档验证后才恢复服务。SQLite 使用独立的一致快照；不可变 HTML 文件先核对路径、长度和 SHA-256，再从原始位置直接压缩读取，不再额外复制一整份快照到暂存目录。

ZIP64、manifest、凭据隔离和最终完整解包/哈希校验保持不变。临时空间主要为数据库快照、实际压缩包和验证解包。压缩前检查归档预算，压缩后按实际剩余容量检查展开预算；失败时不发布归档并清理临时文件。不得在发布者或清理器仍运行时单独调用备份函数。

容量回归使用真实受限文件系统：32 MiB 高熵 HTML 在 118 MiB 与 108 MiB 独立 tmpfs 中完成备份及恢复往返，并核对原文件、恢复文件的哈希和临时目录清理。该测试通过环境变量 `BOOKMARK_TEST_QUOTA=1` 单独启用，`TMPDIR` 必须指向该专用文件系统；常规测试会跳过它。

## 首屏图片缓存

2026-10-16 起，预览 JPEG 是从完整 HTML 生成的可重建缓存，不纳入备份包。备份仍包含 HTML 归档、快照历史与收藏配置。恢复后，worker 在空闲时自动补齐当前版本的图片，历史版本在访问时排入补图；不会为补图重新访问原网站。详见 [ADR-0010](adr/0010-cached-preview-images.md)。
