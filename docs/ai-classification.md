# AI 分类与人工校对

## 2026-10-10：统一目录，避免碎片分类

旧流程每批 10 个网站独立建议新目录，且看不到尚未确认的其他批次目录，容易产生大量近义目录和碎片分类。现在先读取全库的有界标题与域名概况，调用 AI 规划一套持久化的共享目录，再执行每批网站归类。规划阶段最多等待 240 秒；普通分类批次仍为 120 秒。

- 大库最多 8 个一级主题、24 个分类目的地、两层目录；小库按规模缩减。提示词要求合并同义、中英混用分类，按主要用途归类，通常不为单站或单一产品单建目录。
- `ClassificationTaxonomy` 保存目录路径与适用范围，跨批次、重试、重启共用。批次只能选择该词表，后端校验并拒绝词表外路径，不能靠换拼写继续创建分类。
- 完整目录树用于解析已存在的规范路径，不再任意截取前 10000 字符目录列表。人工编辑建议仍可指定其他路径。
- 新分类请求会使所选网站的旧待校对建议失效，并替代完全包含在此次范围内的旧排队、重试或执行中分类任务。旧请求晚到不能继续写回。
- 确认建议后才创建目标目录并移动网站。只清理本次网站原归属及其祖先中因此变空的、具有 AI 创建来源的叶目录；不递归删除，不删除含网站/子目录的目录，也保护仍被待校对建议引用的目录。
- `Folder.created_by_ai` 记录创建来源。人工编辑过的文件夹改为人工管理，不自动清理。旧数据仅通过成功批准记录中的实际新建 ID，与已接受 AI 建议路径、未编辑版本相互印证后补记来源；不能证明的目录保留。

手工目录可继续使用多层级；以上层级和数量限制针对 AI 自动规划。共享方案不因每批成功、批准或重试而重新生成。重新规划词表的交互尚未新增。

2026-10-10 修正：非流式请求的读取等待使用 120 秒响应预算，连接等待仍最多 10 秒；原先额外的 30 秒读取上限会提前中断较慢模型。整体响应耗时继续检查预算。兼容模型内容仅包含一个完整 JSON 代码块的返回，仍拒绝代码块外说明、重复 JSON 键、未知网站 ID 和无效文件夹路径。提示词明确要求纯 JSON 及独立文件夹名称。后台进度区分网站与 AI 批次（每批最多 10 个网站），批次数量按所选网站总数计算；未开始的批次显示排队，重试中的网站单独计数。人工多次提交的批次仍按队列执行。

重试任务会替换原任务组中的失败项，保持网站与批次数不变；共享抓取任务的重试会同步关联所有原任务组。重复点击同一失败任务的重试，在替代任务仍活动时返回同一个任务。

2026-10-09。配置验证、分类建议、人工修改/确认/驳回与重分类已实现，协议及界面验证见 [实现记录](implementation-status.md)，实际供应商兼容需配置后测试。

## 已确认流程

1. 新网页进入收藏库，未确认分类前暂放“未分类”；收藏记录、快照管理与分类方案是不同的状态。已有网页生成新方案时，确认前保留当前归属，不先移入未分类。
2. 软件调用 AI API 判断网页分类，规划目标文件夹和需要新建的目录。
3. 校对页面展示网页、建议路径和待创建目录；用户可以修改。
4. 用户确认后才创建不存在的文件夹并执行归类，每个网站仍最多归属一个文件夹。

确认前可以保存候选方案，但不创建实际收藏文件夹或移动网站。目录创建与归类仍应通过后端统一的数据规则处理，不由模型直接执行数据库操作。

## 已确认的分类规则

- 用户在设置中配置接口地址、密钥和模型名称，不固定供应商。
- 发送网址、标题、简介和有限正文片段，不默认发送完整 HTML 快照。
- 优先复用既有目录，仅在需要时提出新目录，仍须人工确认。
- 浏览器导入可以生成 AI 新分类建议，原目录路径保留作为校对参照，确认前不执行新归类。
- 已进行的分类可以再次调整，包括人工修改和再次生成 AI 分类方案；不因已经人工确认而锁定归属。

已有分类再次调整仍遵循“候选方案、人工确认、执行”的规则。用户本轮明确允许再次调整，但尚未明确是否由定时任务自动发起重分类，不将允许修改等同于自动周期重分类。

## 本次规划采用的交互默认

- 重分类触发：推荐新增网页自动生成方案；已有网页由用户选中网页或文件夹后主动发起；定时刷新只更新快照。
- 校对确认：推荐逐项修改、勾选批量确认；不合适的方案可驳回，保留网页供人工归类或重试。驳回方案不是删除网页。

用户已授权进入技术规划，上述两项作为可调整工程默认，不冒充此前逐项确认的答案。

API 密钥存储、调用时限、结果校验、失败重试、正文片段长度、候选结果失效检测及人工整理入口由实施设计，不要求用户在聊天中提供密钥。

## 协议和执行技术方案

首版采用 HTTPX 同步客户端，对接 OpenAI 风格 Chat Completions 非流式协议；提供商与模型由用户配置。客户端使用明确连接/读取/总时限、响应长度限制、禁止自动重定向和环境代理继承，不把密钥发送到重定向地址。模型参数支持不同，配置测试需验证输出模式与 token 限制字段，测试成功的能力记录后才用于批量任务；不宣称自定义 base_url 即兼容任意协议。[HTTPX](https://www.python-httpx.org/api/#client)、[Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)

输出模式优先使用供应商支持的 JSON schema，否则 JSON object；只返回普通文本的兼容服务仍须经明确测试并严格 JSON/业务校验。不允许“解析失败就把文本当目录名”。响应失败最多按受控策略重试，始终不执行模型提供的工具调用。

正文片段初始上限 6,000 字符、每请求最多 10 个网站、总输入预算 48,000 字符。先用全库的有界标题/域名概况规划共享目录，再仅提供规范目录及其祖先作为候选。后端针对完整树解析规范路径是否已存在，并限制模型只能选择共享目录。结果只包含网站 ID、已有目录 ID 或候选路径、简短理由，见 [API 契约](api-contract.md)。

有成功快照时复用本次采集的标题/正文片段。关闭快照的网页仍可通过同一隔离 runner 的 metadata 模式读取有限信息，不保存 HTML 历史；采集失败可仅凭已有网址/标题生成待校对建议并标记信息不足。AI 未配置或失败时网站仍可管理、手动分类及正常使用已有快照。

密钥保存在运行库 ProviderSecret，配置地址与模型在业务 AIProfile；凭据绑定 endpoint/protocol 及库 epoch。恢复后默认停用 AI 调用直到显式验证，防止旧备份地址套用当前密钥。分类 Job 在业务库，网页抓取与 AI 调用各自失败，不将 AI 响应成功当作已执行归类。

## 刷新后的任务与结果恢复

复用原有任务进度按钮作为“后台任务”入口，按最新布局固定在视口右下角；电脑和手机均可直接打开。入口保留当前任务进度，并显示整库待校对数量；没有任务时同一入口显示空状态。打开页面后从服务器读取持久化任务目录，包含排队、执行、等待重试和已结束记录；本地仅按收藏库 generation/epoch 保存最近查看的任务编号。无本地记录的新设备同样可从任务目录选择任务，不通过重新提交 AI 分类找回进度。

固定区域摘要与历史批次选择分离：服务器在每页任务目录中返回 `current_group`，优先选择最新创建的未结束任务；全部结束时选择最新任务。右下角始终显示该摘要，整库数量明确标注“全库待校对”。点击原入口定位当前任务并回到任务列表第一页。关闭弹窗、刷新页面后也跟踪当前任务，避免浏览器保存的旧批次遮住新工作；弹窗打开时手动查看历史批次的选择保持不变。

每完成一个后台请求（包括成功、失败进入重试、取消的执行尝试），目录响应的全库 `completion_revision` 会变化。前台每 2 秒检查完成记录，发生变化时重新读取页面数据：侧栏摘要、任务详情、网站卡片、快照、目录和已打开的分类建议。仅更新数据，不整页导航，保留当前勾选与历史批次选择。未产生新完成记录的轮询不会重复刷新网站数据；后台标签页保持已有的降频策略。

分类期间持续更新整库待校对数量；后台任务窗口统一通过“校对分类（数量）”打开整库待校对建议，删除本组“查看建议”按钮及其说明，任务批次选择仅用于查看执行进度。已打开的校对窗口自动读取后续返回的结果。后台完成不强制打断当前操作，确认后才创建目录和移动网站。导入原有的“回到导入与备份后弹出校对”规则保持不变。
