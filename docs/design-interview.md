# 网站收藏管理需求访谈

更新日期：2026-10-09。状态：用户表示技术需求基本对齐并委托完整技术规划，已整理为 [technical-plan.md](technical-plan.md)。本文件保留访谈历史，尚未开始软件实现。

## 已确认

- 管理大量网站链接，参考 Eagle 管理图片的可视化体验。
- 同时展示多个网站的页面视觉内容。
- 页面预览只需看到最新页面，无需在预览区域操作网页。
- 多页面展示采用 Monolith 生成的 HTML 网页快照，在卡片中展示首屏；替代 PNG 截图方案。
- 供本人多台设备使用，支持电脑和手机。
- 首版仅联网使用，离线缓存是后续需求。
- 采用前后端分离；前端仅输入密码即可登录，后端可部署在本地或公开服务器。
- 首版只收藏公开可访问的页面，不实现被收藏网站的登录逻辑。
- 首版规模为一千个网站以内。
- 刷新策略同时支持定时刷新和批量立即刷新；最新决定为默认每周刷新一次，替代此前的每天刷新。
- 每个网站可单独配置刷新间隔。
- 批量立即刷新包括一个文件夹及所有子文件夹下的网页。
- 刷新在后台逐个执行并显示进度；失败时保留旧成功快照并标记失败。
- 新增或导入收藏后立即在后台生成快照；后端重启后补刷已到期网站一次，不重放每个错过的周期。
- 支持单站暂停自动刷新而保留手动刷新；另支持网站不生成缓存快照。
- 关闭网站快照功能时保留已有版本，允许查看快照历史；新版本追加，不覆盖旧版本。
- 快照历史默认全部保留，提供手动清理；删除收藏或文件夹时相关快照历史一起删除。
- 支持多级文件夹，不允许一条收藏归属多个文件夹。
- 标签、备注、关键字搜索均为首版必需功能，参照 Eagle 的整理体验。
- 搜索采用部分匹配，默认综合匹配域名、网址、网页名、标签、文件夹和备注；结果只列出相关网站，不分组显示标签/文件夹实体，首版不做网页正文全文索引。
- 搜索框左侧提供“搜索方式”下拉框，弹出复选框列表，可具体选择参与搜索的字段；默认综合搜索，结果始终是网站收藏。
- 相同 URL 全库只保留一条收藏，重复添加时定位已有收藏。
- 浏览器导入重复网站跳过，保留已有记录及配置。
- 删除文件夹同时删除其下收藏；按层级删除其子树，快照文件纳入清理。
- 维护软件自有收藏格式，用于保存软件配置，例如网站独立刷新间隔。
- 提供 Firefox 和 Chrome 浏览器导入方法；浏览器文件导入为候选路径，尚未实测解析。
- 软件密码登录方案采用高质量公开库；已选择 Django auth/session 配合 django-axes。
- 用户明确委托确定技术栈，并要求尽可能轻量；已选 Preact/TypeScript/Vite、Django core/axes/SQLite、自有低并发刷新 worker，部署 Waitress/WhiteNoise。
- 首版必须支持动态网页快照，目标与直接在浏览器看到的页面一致；因此保留 Playwright/Chromium 默认预渲染，按需启动，批次复用并释放。
- 每个启用快照的网站分别保存桌面版和手机版快照，前端按设备展示对应版本。
- 收藏星标为独立按钮，不导航；取消星标保留网站记录和快照历史；点击卡片主体选中，详情在当前界面展开。独立按钮打开原网站继续有效。
- HTML 序列化不等于完整浏览器状态，Monolith 静态重放的视觉保真需验证，不能把“主要内容基本一致”默认为用户已同意的目标降级。
