# 扩展本机收藏库后端 HTTP API、命令行工具与 Agent Skill 规格

日期：2026-10-11。状态：需求已确认并整理为实施规格；尚未实现或验收。本文依据本次访谈、现有领域术语和 ADR 0007、0008 编写。测试方案为本次规格提出的验收设计，不代表已经执行。

## Problem Statement

用户希望直接通过自然语言让本机 Agent 管理网站收藏，例如“创建 Blogs/Games 并把这个链接放进去”，并能查询后台任务、刷新页面快照及请求 AI 分类。当前软件虽已有业务 HTTP API，但依赖网页登录会话，缺少稳定的自动化调用入口、凭据保存和后续 Agent 可发现的操作说明。

现状使 Agent 需要临时研究源码，甚至通过应用模型直接修改收藏库。重复调用、登录过期、服务端口变化及异步结果处理也缺乏统一体验。用户需要一个可复用的正式管理入口，执行结果能核验，且 AI 生成建议与用户审批保持明确区分。

## Solution

扩展现有后端 HTTP API，提供适合自动化的目录复用、收藏添加或更新、可靠重试及后台任务管理契约，并交付仅连接本机服务的轻量命令行工具和可发现的 Agent Skill。工具复用软件现有密码登录、会话与 CSRF 流程；账号密码明文保存在本地，后续会话失效时自动重新登录，并支持清除凭据。不实现 Windows 凭据保存或加密功能。

首版管理范围为网站收藏、收藏文件夹、标签、备注、后台任务、页面快照和 AI 分类。重复添加复用现有对象，明确指定目录时执行移动，省略的字段保持原值。范围内删除遵循现有影响预览和版本校验。

AI 分类只负责向后台提交任务、查询进度、等待并获取待审批结果；用户在软件已有网页中校对和审批。本次工具不提供确认或驳回分类建议的命令。

## User Stories

1. 作为收藏库用户，我希望通过自然语言让本机 Agent 管理收藏，以便减少重复的网页操作。
2. 作为本机 Agent，我希望能发现专用 Skill 和命令行入口，以便在后续会话中直接使用正式接口。
3. 作为本机 Agent，我希望所有收藏管理命令通过 HTTP API 执行，以便遵循与网页一致的业务规则。
4. 作为收藏库用户，我希望首次在终端隐藏输入软件密码，以便完成登录设置而不在聊天或命令参数中暴露密码。
5. 作为收藏库用户，我希望账号密码明文保存在本地配置中，以便后续使用无需重复输入，也无需 Windows 凭据组件。
6. 作为本机 Agent，我希望会话过期后能够自动重新登录，以便继续已授权的操作。
7. 作为收藏库用户，我希望可以清除保存的凭据及本工具会话，以便停止后续自动登录。
8. 作为本机 Agent，我希望准确定位正在运行的本机服务，以便端口变化后仍能连接正确实例。
9. 作为本机 Agent，我希望服务未启动、地址过期或不可用时得到明确错误，以便避免把连接失败误认为业务失败。
10. 作为收藏库用户，我希望查询和搜索收藏及其目录、标签、备注，以便核实当前数据。
11. 作为收藏库用户，我希望创建多级收藏文件夹，以便按主题组织链接。
12. 作为收藏库用户，我希望已有的同级同名文件夹被复用，以便重复执行不会生成重复目录。
13. 作为收藏库用户，我希望重命名和移动收藏文件夹，以便调整组织结构。
14. 作为收藏库用户，我希望添加链接并指定目标目录，以便一次完成收藏和归档。
15. 作为收藏库用户，我希望规范化 URL 相同的链接被复用，以便不会产生重复收藏。
16. 作为收藏库用户，我希望对已有链接明确指定新目录时执行移动，以便“放进某目录”的指令产生预期结果。
17. 作为收藏库用户，我希望修改标题和备注时只改变明确提供的字段，以便其他信息得到保留。
18. 作为收藏库用户，我希望能够明确清空备注或移除目录归属，以便区分清空与不修改。
19. 作为收藏库用户，我希望创建、查询、重命名和删除标签，以便维护分类关键词。
20. 作为收藏库用户，我希望给收藏添加、移除或明确替换标签，以便准确表达不同编辑意图。
21. 作为收藏库用户，我希望批量移动或编辑指定收藏，以便高效完成已确定范围的整理。
22. 作为收藏库用户，我希望删除收藏前能得到影响范围，以便执行的是我指定的数据集合。
23. 作为收藏库用户，我希望删除文件夹时能明确其子树和收藏的影响，以便避免误解递归删除。
24. 作为收藏库用户，我希望预览后发生变化的删除请求被拒绝，以便后来新增或修改的数据不会被默默纳入删除。
25. 作为收藏库用户，我希望触发单站或文件夹范围的页面快照刷新，以便更新桌面和手机预览。
26. 作为收藏库用户，我希望查询页面快照状态和历史，以便了解可用版本及失败原因。
27. 作为收藏库用户，我希望清理指定快照历史并保留现有版本保护规则，以便管理存储而不破坏可用预览。
28. 作为收藏库用户，我希望管理网站快照开关、自动刷新暂停和刷新间隔，以便控制各网站的采集行为。
29. 作为本机 Agent，我希望查询后台任务和任务批次的状态、进度及错误，以便报告真实执行结果。
30. 作为收藏库用户，我希望重试失败任务、取消允许取消的任务，以便管理后台工作。
31. 作为本机 Agent，我希望等待任务超时时保留可继续查询的标识，以便后续恢复跟踪而不重复提交。
32. 作为收藏库用户，我希望为指定网站或收藏文件夹提交 AI 分类任务，以便后台生成整理建议。
33. 作为本机 Agent，我希望只获取本次分类任务对应的建议，以便不会混入其他批次的待审批结果。
34. 作为收藏库用户，我希望 AI 生成结果后由我在网页校对和审批，以便生成建议不会直接改变收藏归属。
35. 作为本机 Agent，我希望遇到分类部分失败、无可用 AI 配置或任务取消时得到明确结果，以便不把终止或失败报告为分类完成。
36. 作为本机 Agent，我希望网络重试不会重复创建对象或后台分类任务，以便超时后的操作仍可追踪。
37. 作为本机 Agent，我希望收到结构化结果、稳定错误码及可靠退出状态，以便后续操作可依据实际结果执行。
38. 作为收藏库用户，我希望这套工具仅连接本机并只交付约定功能，以便管理入口保持明确的使用边界。
39. 作为本机 API 调用者，我希望目录复用、收藏添加或更新和可靠重试由后端 HTTP API 提供，以便直接调用 API 也能获得与命令行工具相同的行为。

## Implementation Decisions

### 已确认的产品决定

- **交付形态**：扩展后端 HTTP API，配套轻量命令行客户端、Agent Skill 和调用文档。不能只把缺失语义写成 CLI 内部编排；客户端管理操作不得直接访问业务数据库或导入应用模型写入数据。
- **功能范围**：网站收藏及其标题、目录归属、星标、标签、备注和网站级快照配置；收藏文件夹与标签管理；任务查询、重试、取消；快照刷新、状态、历史查询与清理；AI 分类提交和结果查询。软件全局设置与 AI 服务凭据配置不属于本次范围。
- **身份机制**：复用密码登录及现有 owner 会话，不引入管理 Token、独立角色或权限系统。所选范围约束本次 CLI 和 Skill 提供的功能；不能将其描述为 owner 会话拥有更窄的服务端权限。
- **凭据体验**：账号密码明文保存于本地配置，首次可通过终端隐藏输入密码，会话过期可自动重新登录；提供清除凭据命令。不实现 Windows Credential Manager、DPAPI 或其他加密凭据存储。文档和 Skill 只记录调用方式及配置位置约定，不记录实际账号密码值。
- **AI 审批边界**：提交后台任务并等待、查询、展示结果；由用户在已有网页审批。客户端不暴露确认、驳回或修改分类建议的命令，不自动移动 AI 建议涉及的收藏。
- **删除体验**：用户明确要求删除后，Agent 可执行查询影响范围及提交两个步骤；不增加一套与现有业务机制重复的审批系统。

### 基于现有实现提出的技术落地约定

以下为满足已确认需求的实施约定，不表示相应能力已经存在。

1. **扩展后端接口和模块边界**：沿用现有版本化业务 API、目录业务层、任务队列和快照流水线，在后端补齐多级目录确保存在、收藏添加或显式更新、请求幂等及必要查询能力。已有 CRUD 继续复用，新增语义采用明确操作契约，避免静默改变网页已有创建行为。新增 HTTP 客户端、本地明文登录配置、服务定位和 Skill 调用说明；核心管理语义须可直接通过 HTTP 使用。
2. **会话流程**：先读取 session 获取 cookie 与 CSRF token，再提交密码登录，登录后重新读取 session 获取轮换后的 token。后续写操作继续携带 cookie 和有效 CSRF，不豁免 CSRF 校验。保持现有会话有效期。
3. **会话恢复**：401 时可重新登录并在确认请求可安全重试后续行；错误密码、登录限流、权限错误或维护状态应明确停止或返回可恢复状态，不能无限循环登录。注销或清除凭据不得撤销用户其他浏览器的全部会话。
4. **本地登录配置**：保存账号、明文密码及本机连接配置，凭据文件不纳入版本控制、规格正文或 issue 内容。现有服务使用固定 owner，保存账号不意味着引入多用户登录；实际登录请求继续遵循现有仅提交密码的契约。会话材料按客户端需要保存，日志与结果不输出密码、cookie 或 CSRF 值。清除操作移除本工具保存的密码和会话；即使服务离线也能完成本地清除。
5. **本机连接边界**：客户端仅接受本机回环地址，禁用环境 HTTP 代理，禁止携带凭据跳转到其他服务。这个约束是管理客户端的连接规则，不新增远程部署方案，也不宣称改变既有网页服务的部署权限。
6. **服务定位**：不能永久假定端口为 8000。优先由服务启动流程在就绪后发布不含凭据的实例及端点信息，客户端核验再连接；保留显式本机地址配置。过期信息、错误实例和失效服务必须报错，不能通过扫描任意端口尝试发送密码。实例信息不构成替代密码登录的认证机制。
7. **命令结果**：管理命令提供机器可读 JSON 结果；机器模式标准输出只包含结果，诊断写到标准错误。退出状态区分成功和失败，异步受理同时返回任务或任务批次 ID。幂等键、请求标识、对象 ID、revision 与状态应在需要续行时可取得。
8. **目录确保存在 API**：后端接受明确的目录分段，逐级按现有名称规范和父目录定位或创建，返回最终目录及哪些节点被创建。不同父目录下同名文件夹不合并；复用目录层级、重名和环检查。创建竞争必须返回唯一目录或明确冲突。一个确保目录请求的数据库变更在单一业务事务中执行。
9. **收藏添加或更新 API**：提供明确的后端复合操作，同时保留已有原始“创建收藏”接口的去重行为。按规范化 URL 定位已有对象；明确传入目录或编辑字段时才更新，省略字段不改，明确空值按字段契约清空。更新已有对象须携带预期 revision；未提供时返回已有对象及版本信息供调用者明确续行，不能绕过并发保护。返回对象、最终目录、revision 和创建/复用/更新结果。标签追加、移除和替换仍以明确操作区分。
10. **事务边界**：单个后端复合请求中的目录与收藏数据库变更使用业务事务；校验失败全部回滚，后台任务在成功提交后登记或调度。多个独立 HTTP 请求不承诺整体原子性；客户端返回已完成步骤及对象 ID 以便续行，不通过擅自删除对象补偿已成功请求。
11. **查询与批量操作**：复用现有查询、筛选、分页和选择能力；完整选择不能只覆盖第一页。保持既有单请求数量限制，超限返回清晰错误，不默默截断或将整批原子操作拆成多个部分成功请求。批量修改保持已有 revision 校验和整体事务语义。
12. **重试与幂等**：自动重放写请求之前先确认服务端具备幂等或等价去重语义。同一逻辑请求在重试时保持相同幂等键，不能重新生成键；同键不同参数返回冲突。重点补齐目录、标签创建及分类提交的可靠重试语义，并验证涉及任务提交的其他命令。对于结果不明且不可安全重放的请求，报告状态未知并提供核查信息。
13. **删除**：收藏、目录子树及快照历史使用适用的影响预览、对象集合、revision 和预览 token 规则；标签删除沿用已有业务契约，不能伪造不存在的 token 流程。预览过期、对象变化或收藏库版本变化时拒绝旧提交，不自动重新预览后扩大删除范围。移除标签只移除标签关联，不能删除关联收藏；清理历史遵守当前有效版本保护。
14. **后台任务和等待**：提交受理与完成分开报告。等待支持有界轮询、超时及中断；停止客户端等待不等于取消后台任务。输出保留任务 ID，以便继续查询；取消必须明确调用任务取消接口。部分失败、重试等待、失败和取消按现有状态准确显示。
15. **AI 分类**：复用分类批次接口、任务批次查询和按批次过滤的建议查询，处理分页。重复提交同一逻辑请求应返回原批次，不能因网络重试取消前一批次或使旧建议失效。使用软件已配置且已验证的 AI 服务；不可用时返回现有错误，不由客户端配置或替换 AI 服务。
16. **网页审批衔接**：结果包含本次 group ID、相关网站及待审批建议，并指导用户进入现有“校对分类”入口。现状未提供按批次打开的网页深链接，不应输出虚构链接；新增深链接不是本次必需功能。报告应区分任务执行终态与是否存在可审批建议。
17. **契约与 Skill**：补全扩展后端 HTTP API 与配套命令的请求字段、分页、清空/省略语义、响应、错误、批量限制和重试要求，更新机器可读 API 契约。Skill 应说明本地账号密码配置、首次登录、调用入口、常见管理流程、删除语义、等待/续行及网页审批，并在后续 Agent 会话可发现。具体命令名称与安装位置在实现时遵循项目和现有 Skill 组织约定。
18. **存储边界**：沿用现有运行身份与业务收藏库分离的架构。凭据与会话不能写入收藏备注、业务任务载荷或可导出的收藏数据。首版不预设新的业务数据表；如幂等与实例信息需要调整存储，保持上述边界。

## Testing Decisions

### 主要验收入口

以**后端公共 HTTP API → 独立测试收藏库与后台 worker**为主要验收边界，直接验证后端扩展的外部行为；另用真实命令行进程通过同一 HTTP 边界串接少量代表性流程。通过 HTTP 状态码、JSON 响应、命令退出状态及后续 API 查询验收，不以内部函数调用次数、SQL 形状或私有字段作为主要断言。

复用现有测试基建和 API 测试。外部 AI 和网页采集使用受控替身，保留真实队列、任务状态和建议持久化流程。用户对初稿明确修订为本地明文账号密码和扩展后端 HTTP API，因此删除 Windows 凭据测试，并将无需 CLI 即可验证的后端行为作为主要验收目标；具体用例是本规格的测试设计。

### 测试先例与模块

- 现有 AuthTests 已通过强制 CSRF 的客户端验证匿名拒绝、密码登录、登录后 token 轮换、注销和登录限流。新增客户端认证验收复用这些行为标准。
- 现有 CatalogTests 已覆盖 revision 冲突、批量修改原子性、同键异参冲突、删除预览变化、分类批次选择及生成任务时不移动收藏。保留这些回归，并将本次客户端流程串接到公共 HTTP 边界验证。
- 后台分类已有进度与重试去重的测试先例；新验收覆盖从命令提交到按批次取回建议的完整路径。
- 被测模块为扩展后的后端 API、命令行客户端与其 HTTP 交互、任务队列衔接、服务定位及明文本地配置的读取与清除。避免为未改变的网页组件新增重复测试。

### 必须覆盖的验收场景

1. **连接和鉴权**：发现正确本机实例、端口变化、服务关闭、过期实例信息；匿名请求拒绝；密码登录后能读写；CSRF 轮换有效；不使用绕过登录的测试会话代替主要端到端验收。
2. **凭据生命周期**：终端设置后后续独立进程可登录；会话失效后自动恢复；密码更改、错误密码和限流不会造成无限重试；清除凭据后不能继续自动登录；本工具退出登录不影响其他浏览器会话。
3. **连接与输出边界**：非本机地址和跨服务重定向被拒绝；环境代理不接收管理请求；本地明文账号密码可按约定读写和清除，记录的输出、错误和日志中不包含凭据。
4. **代表性完整流程**：创建 Blogs/Games，添加一条链接，查询确认路径和对象；重复执行不增加目录或收藏数量；把已在另一目录的链接明确放入目标目录后，标题、备注和省略的标签保持原值。
5. **字段和目录边界**：明确清空备注、移除目录归属；标签追加/移除/替换；不同父目录同名目录；非法目录环和同级冲突；中文及空格名称；路径分段无歧义。
6. **并发与重试**：直接通过后端 HTTP 并发确保同一目录、添加同一 URL；响应丢失后使用同一请求标识重试；同键不同请求冲突；旧 revision 不能覆盖新编辑。单个复合请求失败应回滚，多请求流程失败应报告已完成对象并安全续行。
7. **批量与分页**：跨多页完整查询和选择、边界数量、超限错误、旧版本导致整批拒绝；不能误处理未选中的网站。
8. **删除**：指定收藏和目录子树删除；预览后新增子项或修改数据会拒绝旧提交；不会自动扩大目标；标签删除保留收藏；快照历史清理保护当前有效版本。
9. **快照**：单站和目录范围提交后返回可追踪任务；桌面/手机状态和历史可查询；关闭快照的网站按现有规则跳过；刷新失败保留已有可用版本。
10. **任务**：查询、重试和取消；等待超时后继续通过原任务 ID 查询；中断客户端等待不取消任务；失败、取消、部分失败与成功可区分。
11. **AI 分类**：同一逻辑提交重试只产生一个批次；所选网站包括已分类和未分类条目；只查询本批次全部分页建议；等待时报告进度，结果就绪后仍为待审批，目录结构及收藏归属不被自动改变。
12. **AI 异常**：未配置或未验证 AI、服务失败、部分网站失败、任务取消与重试等待均正确报告；不会伪造待审批结果或发送确认/驳回请求。
13. **网页交接**：使用已有网页入口能找到对应建议并由用户审批；这一小范围手动验收可作为交接证据，无需新增整个网页端的测试体系。
14. **契约与 Skill**：文档示例可由真实命令执行，输出符合约定；后续会话可发现 Skill 和工具，按说明完成代表性流程，无需研究源码或直接访问数据库。

所有自动化测试使用独立数据目录和测试凭据。真实收藏库不作为删除、分类或快照变更的测试夹具。实现完成前不得将这些验收要求描述为已通过。

## Out of Scope

- 远端 Agent、其他电脑及云端访问的部署支持。
- 新增管理 Token、独立管理账户、多用户角色或细粒度服务端授权体系。
- Windows Credential Manager、DPAPI、操作系统密钥库或本地账号密码加密保存功能。
- 导入导出、整库备份恢复、清空仓库、重置数据、软件全局设置和 AI 服务凭据配置。
- 客户端编辑、确认、驳回 AI 分类建议或自动应用分类结果。
- 替换现有采集、AI 分类算法、后台队列或网页登录方式。
- 新建 MCP 服务、通用任意接口执行器，或把数据库直连作为管理工具后备通道。
- 为本次能力重做网页管理界面或保证新的审批深链接。
- 在本次文档交付中编写功能代码、创建真实凭据、部署服务或执行真实收藏库变更。

## Further Notes

- 用户最终要求账号密码以明文保存于本地，并明确扩展后端 HTTP API；这一修订取代此前的 Windows 加密保存建议。自动重新登录和网页审批流程继续保留。
- 现有分类提交尚未具有可靠的请求级幂等保护；盲目重试可能创建新任务批次并使已有建议失效。这是实现必须解决的缺口，不是现有能力描述。
- “本机调用”描述客户端的支持边界；现有 owner 会话权限及网页部署配置必须如实记录，不能将命令集合限制夸大为服务端权限隔离。
- 前一项实际操作“创建 Blogs/Games 并添加链接”是代表性使用场景；验收须在独立测试库中重建同类场景。
- Issue tracker 使用私有 GitHub 仓库 [EiraWalker/Linkarium](https://github.com/EiraWalker/Linkarium)，规格采用 `ready-for-agent` 标签；不要求额外 triage。该仓库按用户指示新建并关联本地项目。
