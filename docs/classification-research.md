# AI 网站分类：研究依据与验收条件

研究日期：2026-10-10（Asia/Taipei）。本文记录公开一手资料及本项目的设计建议，不表示这些建议已实现或达到质量门槛。

## 分类要解决什么问题

分类的目标是让用户按自己熟悉的领域找到资源，并能预期新资源会放在哪里。文件夹数量少、所有网站都有去处、API 请求成功，都不能单独证明分类良好。

NISO 将受控词表的用途概括为一致描述与有效检索，要求界定术语范围、处理同义词和歧义；选词还应考虑实际内容及用户惯用语言。因此，本项目应从使用者选择提供的笔记目录中提取已有的领域划分和用词习惯，再与书签内容对照，不应为了限制为六个大类而合并不同领域。[NISO Z39.19，摘要及 §5.3.5](https://groups.niso.org/higherlogic/ws/public/download/12591/z39-19-2005r2010.pdf)

本地笔记的具体结构由本轮独立目录审计提供；本研究没有读取或上传笔记正文，也不将通用 Obsidian 方法冒充用户正在采用的方法。主题领域、具体项目、模板、附件、收件箱可能承担不同作用，不能把所有物理目录原样复制成网站类别。

## 公开资料支持的做法

| 依据 | 对本项目的应用 |
| --- | --- |
| SKOS 将概念与显示名称分开，提供首选名称、别名、范围说明及例子。 | 为类别保存稳定 ID、规范名称、别名、收录范围和边界例子。“CG 与美术”“CG美术”等应先消歧归一，不能分别创建目录。[W3C SKOS Primer，§2.2、§2.4](https://www.w3.org/TR/skos-primer/) |
| NISO 区分主题、格式、语言等分面，支持用不同属性检索同一资源。 | 主目录按主题或工作领域组织；“文档、教程、社区、工具、素材”等资源形式通常使用标签。跨领域的第二用途也用标签表达；具体取舍遵循本地审计结果。[NISO Z39.19，§5.3.4](https://groups.niso.org/higherlogic/ws/public/download/12591/z39-19-2005r2010.pdf) |
| Anthropic 分类指南先调查人工工作方式，再定义类别、提供示例及多意图优先规则；类别较多时可按层分类。 | 先形成共享分类规则，再让各批次从规则内选择。用真实易混淆样例解释边界；每批独立发明目录会破坏全库一致性。[官方分类指南](https://platform.claude.com/docs/en/about-claude/use-case-guides/ticket-routing) |

## 建议的最小实施流程

以下是据上述资料及项目约束形成的工程建议，不是来源规定的通用算法。

1. **建立用户分类档案。** 只提取与资源检索有关的目录名称、父子关系、别名和必要的统计。区分主题与笔记管理用途。用户确认的分类与历史 AI 自动创建目录分别标识，旧 AI 目录不能自动成为学习真值。
2. **形成有版本的目录方案。** 每类包含 `id`、`path`、`scope`、`exclude`、`aliases`、正例及反例。可以直接归入合适的父类；只有具有独立检索用途的子主题才拆分。根目录数、深度和成员数是诊断指标，不以均分数量为目标。
3. **固定方案后逐批分类。** 输入包含标题、URL、已有标签/备注、原浏览器路径、可用的网页正文摘要及抓取状态。始终传入相同版本的分类规则；返回书签 ID、类别 ID、简短依据、可选标签，或 `needs_review` 及原因。禁止批次擅自新增路径。
4. **处理缺口和不确定项。** 无法匹配的真实新领域进入待规划集合，在全库范围评估后再修改方案；信息不足、跨领域边界不清与类别缺失分开记录。待人工项计入工作流程已处理数，不算 AI 错误重试，也不算已经正确归类。
5. **先验收，再扩大执行。** 对同一批有代表性的书签比较新旧结果；保存模型、提示词、分类版本及输入修订号。过期请求结果不得覆盖新方案的建议。
6. **保留人类校对。** 接受建议后才移动网站；按既定约束只清理由本次移动变空、可确认 AI 创建的旧目录。人工调整作为后续边界样例，不能在再次运行时被无条件覆盖。

轻量实现可先使用 JSON 分类档案、现有 SQL 数据及现有标签功能；少于千条资源无需仅为套用检索增强示例而引入向量数据库。

## 良好分类的验收条件

以下数值是本项目建议的初始门槛，应通过真实标注调整，不能报告为已达成或行业标准。

| 条件 | 如何检查 |
| --- | --- |
| 目录有明确含义 | 每个目标类别有范围和排除规则；抽查相邻类能解释差异。标题不是“技术与生活”等无关领域拼接。 |
| 同义与分面不混乱 | 规范化后重复路径为 0；语义同义目录人工复核为 0；主题相同但资源形式不同的网站能在同一主题下找到。 |
| 每项结果有合法语义 | 所有返回项目属于该批次，类别属于当前版本，ID 不重复；缺失、失效或信息不足有明确状态。此项工程验证要求 100%。 |
| 主题准确且覆盖真实兴趣 | 先建立约 40–60 条独立分层测试样本，覆盖主要领域、中文/英文、抓取失败、交叉用途和长尾；有充分依据样本的主领域正确率暂定至少 90%。分领域分别报告，不能用多数类别掩盖小类别。 |
| 不依赖批次碰巧怎样分组 | 对相同样本改变输入顺序和批次组合重复分类，主题一致率暂定至少 95%；白名单有效不代表语义一致。 |
| 不确定性诚实可见 | 报告可判定比例、待人工比例及明确判断的正确率；独立检查无意义标题、空内容和互相冲突证据。不能通过全选“待人工”获得虚假的高准确率。 |
| 结构粒度服务于查找 | 展示目录分布、同义候选、单项目录和大杂烩目录供检查；单项类别不是自动错误，少数项也可以属于真实长期领域。不得仅为凑数自动合并。 |
| 便于使用且可回溯 | 用常用资源做检索任务，检查目标路径是否可预期；记录人工改类比例和原因。批准前显示目标与依据，保留版本及原位置信息。 |

以上门槛只约束如何判断改进，不能用几个成功 API 请求、单元测试通过或更整齐的文件夹数量替代分类质量结论。
