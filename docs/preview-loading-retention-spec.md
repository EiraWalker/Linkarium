# 当前页页面预览完整加载与跨导航保留

状态：已按 [GitHub Issue #2](https://github.com/EiraWalker/Linkarium/issues/2) 实现，2026-10-15 浏览器验收通过；实施证据与限制见 [验收记录](implementation-status.md)。

2026-10-16 更新：用户已授权采用首屏图片缓存加速，见 [ADR-0010](adr/0010-cached-preview-images.md)。下文关于 HTML iframe、不使用图片的旧实现约束被该决定替代；当前分页完整加载、跨导航复用、设备与版本身份、登录与删除清理仍适用。

## Problem Statement

用户通过网站收藏卡片中的页面预览识别和浏览网站。目前只有进入可见区域附近的预览才获得加载资格；预览还受桌面最多 8 个、手机最多 4 个 iframe 的保留上限约束。已显示的预览离开候选区域或超出上限后会被卸载，再次滚回时重新创建和加载。

这使用户在同一列表页内上下浏览时反复等待，未进入屏幕的卡片也不会提前准备好。翻页、切换收藏文件夹或离开列表再返回时，同样无法继续使用先前已加载的预览。

## Solution

进入一个网站收藏列表页后，该页全部具有可用页面快照的卡片自动进入加载队列，包括尚未进入屏幕的卡片。允许限制同时加载的数量，已完成的项目持续保留，剩余项目继续推进；用户无需滚动来触发加载。

同一次应用运行期间，已加载的页面预览在滚出屏幕、翻页、切换收藏文件夹以及应用内切走再返回后继续可用。返回相同快照时直接展示已加载结果，不重新经历预览加载过程。刷新整个网页后允许重新加载。

“当前页”指当前分页返回的网站收藏，现有默认每页 48 条；本规格不预加载尚未访问的其他分页，也不一次加载整个收藏库。页面预览继续展示已保存的 HTML 页面快照及其首屏内容。

## User Stories

1. As a 网站收藏浏览者, I want 打开列表页后该页所有可用页面预览自动进入加载队列, so that 不必逐张滚到卡片前才开始等待。
2. As a 网站收藏浏览者, I want 屏幕外的卡片也能完成预览加载, so that 稍后向下滚动时可以直接辨认网站。
3. As a 网站收藏浏览者, I want 预览分批加载且队列持续推进, so that 页面保持可操作并最终完成整页加载。
4. As a 网站收藏浏览者, I want 页面上先完成的预览立即可见, so that 不必等到整页全部完成才开始浏览。
5. As a 网站收藏浏览者, I want 向下滚动后上方已加载的预览保持可用, so that 回到上方时无需重新等待。
6. As a 网站收藏浏览者, I want 向上滚动后下方已加载的预览保持可用, so that 来回浏览不会反复加载。
7. As a 网站收藏浏览者, I want 翻到另一分页再返回时继续显示原页已加载的预览, so that 比较不同分页的网站时不丢失浏览成果。
8. As a 网站收藏浏览者, I want 切换收藏文件夹后再返回时保留已加载的预览, so that 在分类之间切换时仍能顺畅识别网站。
9. As a 网站收藏浏览者, I want 应用内离开网站收藏列表再返回时保留已加载的预览, so that 查看其他功能不会清空浏览成果。
10. As a 网站收藏浏览者, I want 使用应用内导航以及未刷新文档的浏览器前进后退时适用相同保留规则, so that 导航方式不会改变预览体验。
11. As a 网站收藏浏览者, I want 仅加载当前访问分页的预览, so that 打开一页不会额外加载整个收藏库。
12. As a 网站收藏浏览者, I want 刷新整个网页后允许重新加载预览, so that 本次改进不要求跨刷新保存完整快照内容。
13. As a 桌面用户, I want 当前页超过 8 张卡片时仍能全部完成加载并保留, so that 后面的卡片不会因旧保留上限而长期停留在占位状态。
14. As a 手机用户, I want 当前页超过 4 张卡片时也适用完整加载和保留规则, so that 手机浏览不再反复丢失已加载的预览。
15. As a 网站收藏浏览者, I want 单个预览失败或超时时其余预览继续加载, so that 一个异常快照不会阻塞整页队列。
16. As a 网站收藏浏览者, I want 无快照收藏继续显示原有缺失状态, so that 缺失内容不会被当作未完成加载而无限等待。
17. As a 网站收藏浏览者, I want 快照功能关闭但已有页面快照的收藏仍按现有规则预览, so that 停止生成快照不会妨碍查看已有内容。
18. As a 网站收藏浏览者, I want 桌面快照与手机快照分别对应正确的已加载结果, so that 切换设备版本时不会看到错误布局。
19. As a 网站收藏浏览者, I want 新页面快照可用后展示对应新版本, so that 保留机制不会把旧版本误当作当前版本。
20. As a 网站收藏浏览者, I want 打开详情及快照历史后仍能查看所选版本, so that 列表预览改进不会破坏已有查看能力。
21. As a 网站收藏浏览者, I want 保留预览维持现有首屏比例与交互方式, so that 识别网站、选中卡片和打开原网站的操作保持一致。
22. As a 收藏库使用者, I want 退出登录或收藏库被替换后清理旧预览, so that 旧会话和旧收藏库的内容不会继续出现在当前界面。

## Implementation Decisions

- **沿用项目术语与快照形态。** 页面快照为已归档的 HTML 内容；页面预览是其视觉展示。继续使用受限制的 iframe 展示首屏，不将实时网页或 PNG 缩略图作为本次替代方案。
- **分页决定加载集合。** 网站收藏列表在当前分页元数据就绪后，将该页全部可用快照交给预览管理模块。可见性可以影响排队优先级，不能决定某张卡片是否永远获得加载资格。可见区域不变化时，队列也必须最终处理完整页。
- **分离加载并发与已完成结果保留。** 保留有限加载并发和逐项完成、失败、超时释放额度的机制。现有桌面 2、手机 1 的并发可作为实现起点，不作为必须固定的产品参数。现有桌面 8、手机 4 的挂载保留上限不得继续淘汰已完成预览或阻止整页完成。
- **预览生命周期提升至应用运行期。** 同一管理模块持有跨分页和应用内导航可复用的已加载结果，卡片离屏或暂时离开当前页面不会释放该结果。仅保留组件局部状态、URL、HTTP 缓存或 HTML 字符串不足以证明返回时无需重新加载；实现须通过浏览器行为验证。
- **保留适用于相同快照。** 结果身份至少区分当前收藏库身份、页面快照版本和桌面／手机版本，避免因卡片复用、文件夹变化或设备切换错配内容。同一快照在不同列表中出现时应复用已完成结果，不以列表组件实例作为其唯一身份。
- **导航与可见性不触发清空。** 同页滚动、翻页、收藏文件夹切换、应用内离开和返回，以及不刷新文档的浏览器前进后退，均不能清空已完成结果。浏览器标签页暂时隐藏也不应单独触发已完成结果淘汰；浏览器在后台对新请求的调度不作完成时限承诺。
- **未完成请求以当前页面为先。** 新访问页自动入队；离开旧页时可以取消或暂停尚未开始的旧页工作。已经完成的结果必须保留。未访问分页不提前抓取或预加载；本规格不要求离开的页面继续完成尚未加载的全部项目。
- **管理有效性与释放时机。** 整个网页刷新允许从空预览状态开始。退出登录、会话失效、收藏库身份变化、整库恢复或重置时清理旧预览；已删除收藏及已删除快照不再作为可复用结果展示。新快照版本出现时展示正确版本，不把旧缓存挂在新版本信息下。既有历史版本仍按快照历史功能访问。
- **保持故障语义。** 加载失败或超时释放队列额度，其他项目继续推进。沿用已有无快照及预览未加载状态；iframe 的 load 事件不能被当作抓取成功、HTTP 成功或内容完整的唯一证据。缓存与预览失败不改写后端采集结果。
- **保持私有快照隔离。** 沿用鉴权预览接口、同站点地址检查、空 sandbox、后端 CSP 与不可交互卡片预览等约束。保留机制不能扩展归档脚本权限、将归档插入应用 DOM，或绕过登出后的访问限制。
- **限定改动模块。** 涉及网站收藏列表、共享预览管理与展示、应用会话及收藏库身份变化时的清理接入。详情与快照历史通过已有预览入口保持兼容。无需新增数据库表、后端业务接口、采集任务或新的状态管理框架。
- **同步架构约定。** 实施时记录一项后续架构决定，明确替换旧“按可见区域挂载、离屏与翻页卸载、限制保留数量”策略；同步前端方案、验收基准与技术方案中的相关描述，并保留 HTML 快照、权限隔离及历史版本决定。历史验证记录只描述当时结果，不改写为本次已通过的证据。

## Testing Decisions

- **主要测试入口为浏览器中的收藏浏览流程。** 使用真实构建后的应用、隔离验收服务与可控 HTML 快照夹具，贯穿网站收藏列表、导航和共享预览管理。优先复用现有 Playwright 浏览器验收与独立测试库模式，不单独为各内部缓存结构建立测试入口，也不以私有 Map、候选集合或组件状态作为验收对象。
- **既有先例。** 当前项目已有跨页选择和收藏文件夹操作的真实浏览器验收，覆盖界面点击、分页、请求观察及独立测试数据清理；已有预览夹具将经验证的桌面／手机 HTML 归档发布至隔离验收库。这些机制可复用，原有预览池“离屏卸载、最多 8／4 个”的成功断言需要按新规则替换。
- **整页完成而无需滚动。** 构造足量快照，使当前页达到现有 48 条，并确保初始视口外有卡片；停留在页首，等待全部正常夹具的预览文档成功加载。记录每个版本的请求和文档加载事件，随后滚到页面末端，确认内容已经可见。仅有请求发出、iframe 节点存在或固定延迟结束均不能证明加载完成。
- **双向滚动保留。** 等待整页成功加载后，从顶部到底部再返回并重复往返。观察预览内容和加载事件，确认相同快照没有重新经历占位等待或文档加载。不能只依赖网络请求计数，因为从浏览器缓存重建文档仍可能产生用户可见的重复加载。
- **跨导航保留。** 覆盖第一页到第二页再返回、收藏文件夹切换再返回、应用内其他功能页再返回，以及未刷新文档的浏览器前进后退。确认已完成的相同快照直接显示且未重新加载；新增页仍完整入队，未访问页没有自动预加载。列表元数据是否重新请求不作为本项失败条件。
- **生命周期例外。** 刷新整个网页后重新加载允许通过；退出登录、会话失效或替换收藏库后，旧预览应退出界面且不能作为新身份的复用结果。验证同一收藏的新快照、桌面／手机版本和历史版本不会串用。
- **队列容错。** 混入正常、缺失、失败和超时夹具，确认有问题的项目不会使其他正常项目永久滞留。验证已关闭快照生成但仍有历史内容的收藏继续可预览。
- **桌面与手机布局。** 在两种浏览器视口下执行整页、滚动和返回场景，验证首屏缩放、卡片操作、详情及版本选择兼容。浏览器手机模拟的结果与实体手机结果分别记录，不能将前者标记为真机验收。
- **安全与视觉证据。** 在同一浏览器入口观察受限预览、关键页面截图和请求结果，验证未改变 sandbox、鉴权及归档权限。仅凭类型检查、构建或后端测试不能声明该交互问题已解决。
- **资源证据。** 对整页完成、访问多页及往返后的资源使用和响应情况记录实测数据，区分正常的首次保留增长与重复打开相同快照造成的额外增长。本规格没有用户确认的新内存阈值或自动淘汰规则；不能为了满足旧挂载数量断言而重新引入预览丢失。
- **交付检查。** 实施阶段执行现有类型检查与生产构建，以及上述浏览器验收；仅在改动实际触及后端契约或安全响应时扩大相应回归。当前规格编写不表示这些检查已经执行或通过。

## Out of Scope

- 跨整个网页刷新、关闭浏览器或重新打开后的预览持久化保证。
- 跨浏览器标签页、跨浏览器或跨设备共享已加载的前端结果。
- 预加载尚未访问的其他分页、收藏文件夹或整个收藏库。
- 离开页面后仍保证其全部未完成预览继续在后台加载。
- 新增离线模式、Service Worker 缓存产品能力或在本地存储中长期保存完整页面快照。
- 改变快照采集、定时刷新、快照历史保留策略和归档格式。
- 用 PNG 缩略图替换 HTML 页面预览、修改卡片布局或新增卡片大小设置。
- 自动淘汰已完成结果后让用户重新等待的资源降级规则；如实施实测出现资源不可接受的情况，应另行明确取舍，不能静默缩小已确认的保留范围。
- 扩展跨导航的滚动位置、表单草稿或列表元数据持久化规则。

## Further Notes

- 已确认的四项产品边界：整页开始加载、同页双向滚动保留、切走再回来保留、刷新整个网页允许重载。允许排队，不要求同时发出整页请求。
- 当前卸载行为源于既有资源策略，与早期架构及验收基准一致；本规格有意调整该策略。实施需要同时处理加载资格、已完成结果保留和跨导航生命周期，仅扩大预览池数量无法覆盖全部要求。
- 当前需求不承诺返回前已经完成的内容之外的页面也全部预加载，不承诺跨刷新离线可用，也未确认无限浏览量下的性能指标。
- 规格编写阶段只定义需求；实施结果另记于验收记录。本功能不要求修改正式收藏库或重新采集快照。
