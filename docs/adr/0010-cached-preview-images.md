# HTML 归档保留，默认首屏预览使用缓存图片

2026-10-16 用户要求减少快照页面加载时间，并明确允许刷新采集时缓存首屏图片。此决定更新 ADR-0004、ADR-0009 中默认以 HTML iframe 展示首屏的部分；Monolith HTML 仍是完整快照和历史的保存格式。

采集器在已有的断网重放与质量检查通过后，对同一页面截取首屏 JPEG（质量 82、CSS 像素、桌面 1366×768／手机 390×844）。不重新访问原网站，不截整页，也不以图片成功替代 HTML 的质量检查。图片生成失败不会撤销有效 HTML，后台可单独补图。

默认列表、详情与历史预览加载图片。详情的“查看完整快照”显式打开所选版本的受限 HTML，原网站入口保留。每个已访问分页仍加载全部可用预览，同一应用运行期共享图片请求与 object URL，跨滚动、分页、文件夹和应用内导航复用。退出登录、库身份变化和删除仍清理缓存。

派生图位于当前 generation 的 `previews/v1/`，身份包含 HTML 内容哈希、设备、视口和缓存格式版本。新增快照发布时写入图片；已有当前版本由单个业务 worker 空闲时逐项补图，用户正在查看的缺图优先，历史按访问补图。补图只读取已保存 HTML，禁脚本、阻断外连、使用 Chromium sandbox 和仅提供单份文档的本机代理；子进程有总时限，维护时终止进程树。图片失败单独退避，不修改抓取任务及原有快照失败原因。

`thumbnail_url` 为新增鉴权 JPEG 端点；原 `preview_url` 保持 HTML 含义。缺图返回 202 和 Retry-After，不在 Web 请求里启动浏览器。图片返回私有缓存和 ETag，每次网络复用都重新鉴权；前端本次会话直接复用已下载图片。HTML 的 CSP、sandbox、no-store 保持原值，应用 CSP 仅在 img-src 中增加 blob: 支持已验证 JPEG 的本地显示。

JPEG 属于可重建缓存，不写入数据库或备份包，不增加迁移和备份格式版本；备份仍保存完整 HTML 和所有历史，恢复后自动补当前版本，历史访问时补图。孤立图片随已有归档清理流程回收。缓存不代表离线功能，也不改变已保存网页是否成功的判定。
