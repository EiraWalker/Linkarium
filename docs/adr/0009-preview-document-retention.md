# 当前分页完整加载，并按应用运行期保留页面预览

2026-10-16：[ADR-0010](0010-cached-preview-images.md) 将默认展示载体改为缓存首屏图片。本文的完整分页加载与跨导航保留要求继续适用，iframe 实现细节成为历史记录。

2026-10-15，用户确认 [Issue #2](https://github.com/EiraWalker/Linkarium/issues/2)：进入列表页后，当前分页全部可用快照开始加载，允许排队；上下滚动、翻页、切换收藏文件夹或应用内离开再返回时，已加载预览保留；刷新整个网页允许重载。

本决定替换 ADR-0004、ADR-0005 及早期前端方案中按可见区域挂载、离屏和翻页卸载、桌面 8／手机 4 个挂载上限的部分。HTML 归档、首屏展示、独立桌面／手机快照、历史保留、鉴权和空 sandbox 等既有决定继续适用。

比较了缓存完整列表页面子树与独立保留快照文档两种实现。前者能保留同一个查询下的 iframe，但不同目录、筛选和详情会重复持有内容，并将元数据和表单状态带入缓存。采用后者，以快照版本、设备和预览地址识别文档，由应用会话内的共享模块持有。

iframe 始终附着在各自稳定的列表／详情滚动容器内，宿主采用滚动内容坐标的绝对定位。原生滚动同时带动卡片与预览，不依赖 scroll 回调、逐帧读取祖先样式或 JS 更新屏幕坐标。列表内容使用 Preact 自带的 portal 放入稳定容器，离开页面时卸载列表和表单、隐藏容器，保留的文档不移动父节点。普通 DOM 重挂载会重置 iframe；支持保留状态的 moveBefore 尚非所有主流浏览器都可用，因此不将其作为必要条件。[MDN moveBefore](https://developer.mozilla.org/en-US/docs/Web/API/Element/moveBefore)、[Preact createPortal](https://preactjs.com/guide/v10/api-reference/#createportal)

同日后续修正：最初的 body 固定定位实现需要在 scroll 之后再等待 requestAnimationFrame 更新坐标，浏览器已滚动而预览仍留在旧位置。6 张预览的最小浏览器复现当帧错位 80px、停稳后 0px。改为上述稳定滚动容器后，桌面／手机模拟视口在 6 张、48 张、滚轮输入及详情滚动场景的当帧错位均为 0px；原有加载和跨导航保留验收重新通过。

此处允许使用现有 Preact 包从 compat 入口导出的 createPortal，细化早期前端方案对兼容层的限制；只使用这一内置入口，不增加 React 运行时或其他依赖。

当前分页全部项目入队，详情优先、可见卡片其次，其余卡片继续推进。桌面加载并发 2、手机 1，与已完成文档数量分开计算。不预加载未访问分页；离开页面后取消未启动工作，已发起请求允许在隐藏宿主完成。同一快照在同一稳定滚动区域内复用；卡片和详情属于不同滚动区域，可以分别持有文档，避免跨父节点移动后重载，不随往返次数重复创建。

预览地址先做 HEAD 检查，验证鉴权、状态和 HTML 内容类型，随后 iframe 请求 GET。扩展既有资源的方法，不增加业务端点或数据库结构；HEAD 返回与 GET 相同的权限、CSP、no-store 和内容类型，正文为空。检查失败或 15 秒加载超时释放队列额度，迟到的文档加载仍可恢复显示。iframe load 不改写后端抓取结果。

会话失效、登出、收藏库身份变化或整库替换会销毁整个预览会话。删除收藏和历史时释放对应文档；删除文件夹后通过现有收藏选择接口核对剩余 ID，保留不相关收藏的文档。新快照版本使用独立身份，不会把旧文档显示为新版本。

代价是内存随本次运行访问过的不同快照数量增长，而非固定在 8／4 个文档。规格未授权自动淘汰后让用户重载，也未给出新的内存阈值。应分别记录小型夹具和实际归档的资源证据；浏览器模拟手机不能代替实体手机或大量大型归档的性能结论。

验收使用构建后的真实应用与隔离浏览器 API 夹具，观察快照请求、文档导航事件、界面操作和截图。重点是离屏完整加载、往返不重载及生命周期清理，不断言私有缓存结构或旧挂载上限。
