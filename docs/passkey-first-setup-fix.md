## 行为

已有所有者、当前网站尚无 Passkey 时，匿名登录页直接显示“创建第一个 Passkey”。`passkey_initialize` 为此状态签发成功使用前不过期的单次数字授权码，直接在普通 `/login` 输入；成功登记保留原所有者、文件密钥和所有收藏数据。没有所有者时同样使用不过期的首次初始化码；已有 Passkey 时不能签发此类授权。

服务端独立使用 `first_passkey` 授权用途和 `first_passkey_code` 请求字段，绑定所有者、来源、RP ID 及认证版本；错误五次锁定，重新签发替换旧码，最终提交再次检查当前 RP 仍无 Passkey。两个已取得的 challenge 不能登记出两把首个凭据。原有新设备链接＋独立码、终端重置和本机已登录添加保持各自授权规则。

后续按用户要求取消首次授权码的时间期限。迁移 `0004_initial_passkey_no_expiry` 将当前未消费且未撤销的首次码改为无截止时间，保留原码摘要及错误次数；服务重启保留有效码，手动重发替换旧码。成功注册才消费；单次注册 challenge 仍为三分钟，新设备授权五分钟、重置授权十分钟。下文的无迁移验证记录属于取消期限之前的入口修复。

授权链接进入后清除地址栏片段，将待配置意图暂存当前标签页的 `sessionStorage`。刷新恢复同一表单和同一客户端截止时间；成功、失败终结或到期时清除。输入的授权码不保存。服务端原始到期时间始终是最终依据。浏览器禁用会话存储时保留片段，支持刷新。
