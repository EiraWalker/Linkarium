# 从资源集合归纳分类体系：一手研究与轻量方案

核验日期：2026-10-10（Asia/Taipei）。研究对象是少于 1,000 条、跨领域、中英混合、证据完整度不一的个人网站书签，以及用户提供的 Obsidian 参考目录。本文只研究方法；未向用户配置的 AI API 发送请求，未执行重新分类，也未修改应用或 skill。

## 结论与任务定义

建议采用 **全库证据盘点 → 分片发现候选主题 → 全局合并并形成目录草案 → 展示草案 → 固定目录逐项归类 → 根据未覆盖项修订目录**。这是结合 TopicGPT、LLooM、Clio 和 TaxoAdapt 的本项目工程建议，尚未经本库对照实验验证。

问题需要拆成两个阶段：

- **分类体系归纳（taxonomy induction）**：从资源中发现应该有哪些类别、各类边界与层级，回答“目录如何产生”。
- **资源归类（assignment）**：按照一套明确的目录判断每个资源去哪里，回答“这个链接属于哪类”。

只改分类提示词或先固定几个宽泛大类，解决不了第一阶段。先验目录、聚类结果和模型常识都应视作候选证据；最终类别需要能解释实际资源，并符合用户查找习惯。

## 七组主要一手依据

### 1. TopicGPT：发现、归并和逐项归类分阶段

**原文事实。** NAACL 2024 论文先让模型依次读取样本文档和已有主题，复用或增加可泛化主题；主题由名称和描述组成。随后语义合并近重复主题，最后把固定主题列表用于文档归类，并输出支持该归类的原文引用。作者对低频删除阈值明确要求谨慎，避免删掉重要主题；评估涉及英文 Wikipedia 与美国法案摘要。[论文 §3–4](https://arxiv.org/html/2311.01449v2#S3)，[正式论文页](https://aclanthology.org/2024.naacl-long.164/)

**本项目推断。** 这是最适合复用的基本工作流。书签量不大，可让全部有效证据至少参与一次候选发现，不必只看固定前几十条。把原文的逐文档增量发现改为小批候选发现后全局归并，是减少请求数量的工程变体，不能声称原论文已经验证了该变体。不要照搬其低频删除规则：个人收藏中的单个专业资源可能非常重要。

### 2. LLooM：先提炼证据，再归纳有判定条件的概念

**原文事实。** CHI 2024 的流程为 Distill → Cluster → Synthesize：从文档提取或概括要点，汇总后做嵌入聚类，再由 LLM 生成概念。概念包含可理解的描述、明确收录条件和代表性样本；可循环得到更高层概念，也能由用户指定观察角度。作者指出小样本可能不代表全库，概念仍需应用回完整数据检查覆盖。[论文 §3.1、§4.5](https://arxiv.org/html/2404.12259v1)，[作者研究页](https://idl.uw.edu/papers/lloom-concept-induction)

**本项目推断。** 目录名称不够，必须保存“什么会被放进来、什么不会”。例如“人工智能”与“游戏开发”的冲突不能仅靠名字解决；可以规定通用模型和 Agent 工具放前者，直接服务关卡、游戏代码或游戏资产工作流的材料按其主要用途归入后者，并用标签表达 AI 属性。具体边界应从实际资源和用户目录提炼，而不是预先宣称该例适合所有收藏。

### 3. Clio：局部发现后必须全局去重、再分配、再命名

**原文事实。** Anthropic 的 Clio 先抽取对话分面摘要，嵌入后用 k-means 聚类，再由模型描述簇。层级阶段按邻域提出上位概念，参考邻域外的近邻，跨邻域去重后重新分配子簇，最后根据真实成员重写父类名称。作者承认摘要错误、稀有主题遗漏、过宽标签及错误层级等限制，输出需要进一步核验。[论文 §2.2、§5、附录 G.7](https://arxiv.org/html/2412.13678v1)

**本项目推断。** 当前“每批生成自己的文件夹”缺少的正是跨批次归并。各分片只能输出候选概念及支持资源 ID，不能直接建立目录；所有候选统一合并后，再回看成员是否符合名称。Clio 面向大量对话的统计探索，其隐私聚合和低频抑制目标不应移植为个人书签的类别删除规则。

### 4. TaxoAdapt：用实际归类暴露的缺口决定扩宽或加深

**原文事实。** ACL 2025 的 TaxoAdapt 允许用用户指定目录替代初始 LLM 目录。它按维度和层级归类：某叶节点积累足够论文时考虑向下细分；父类中许多论文无法落入现有子类时考虑增加同级分支。新子主题结合父类、祖先路径、现有兄弟节点和对应论文归纳。主要实验为科学论文语料，多项指标由 LLM 评判并辅以人工核验。[正式论文](https://aclanthology.org/2025.acl-long.1442/)，[方法 §3、评估 §4](https://arxiv.org/html/2506.10737v1)

**本项目推断。** Obsidian 目录适合作为词汇、层级和用户关注点的种子；它不应迫使陌生网页进入不合适的已知领域。目录修订应由未覆盖项、明显混杂的类别和实际查找需要触发。论文的密度阈值、科学贡献维度、多父节点结构不能直接复制：本产品主文件夹要求单一归属，额外维度可通过标签表达。

### 5. TaxoGen：广义资源可以停在父级，局部语义需要局部分析

**原文事实。** KDD 2018 的 TaxoGen 递归构造主题层级，使用词项嵌入、自适应球面聚类及局部嵌入。它指出通用词项不应全部塞入细分子主题，而应留在父主题；全局嵌入在细粒度子领域的区分能力也可能不足。[论文 §4.2–4.3](https://arxiv.org/pdf/1812.09551)，[KDD 正式介绍](https://www.kdd.org/kdd2018/accepted-papers/view/taxogen-constructing-topical-concept-taxonomy-by-adaptive-term-embedding-an)

**本项目推断。** 综合入口、完整手册等可以属于父目录，不必为了“全部落到叶子”创建“其他”子目录。需要细分某个专业分支时，单独检查该分支资源，减少其他领域的干扰。原方法需要从语料学习词项表示；对数量少、标题短且缺失内容的书签，完整复刻它不是当前轻量实现的首选。

### 6. BERTopic：聚类负责找相似资源，LLM 可负责解释簇

**原文事实。** BERTopic 的默认主流程是文档嵌入、降维、聚类、c-TF-IDF 主题表示；其生成式表示模块把关键词和代表文档送给 LLM 命名，并支持增加样本多样性，防止几份近重复文档主导描述。[官方算法说明](https://maartengr.github.io/BERTopic/algorithm/algorithm.html)，[官方 LLM 表示说明](https://maartengr.github.io/BERTopic/getting_started/representation/llm.html)

**本项目推断。** 如果以后资源更多，或已有可用嵌入服务，这是一条合理升级路线。相似性只能提出候选组；同为“在线工具”的绘画、财务、编程网站可能字面相似，却不应必然成为主目录中的邻居。对当前规模，额外模型、依赖、缓存和聚类参数的成本需要和质量收益一起评估，不能默认“使用向量”就会变好。

### 7. Lost in the Middle：上下文放得下，不等于所有资源都被有效处理

**原文事实。** TACL 2024 研究在多文档问答和键值检索任务中发现，相关信息的位置会影响当时受测模型的表现，较长上下文中部的信息尤其可能被忽略。[正式论文页](https://aclanthology.org/2024.tacl-1.9/)

**本项目推断。** 这不能证明当前模型一定无法一次处理 1,000 条书签，也不是分类算法的直接对照实验；它说明需要实际检查长输入的覆盖与顺序敏感性。全库一次提示可以保留为基线，但不应只因输入未超上下文上限就认定可靠。

### 检索到但未采用的名称：TaxonomyLLM

检索到的 `mgorav/TaxonomyLLM` 项目自述的主要任务是将数据库等 logical schema 转成 RDF taxonomy，并描述了专门训练方案，和从个人网页集合归纳主题目录并不相同。本次未核验到能对应其具体效果主张的正式评估论文，因此不将该项目作为主要方法依据，也不依据其项目名推荐采用。[该仓库说明](https://github.com/mgorav/TaxonomyLLM)

## 四条路线如何选择

以下是结合上述研究、针对本项目的工程比较，不是这些论文之间同条件的性能排名。

| 路线 | 具体做法 | 优点 | 主要问题 | 当前判断 |
| --- | --- | --- | --- | --- |
| 全库一次提示 | 把所有简明资源卡、参考目录和原则放入一次上下文，同时请求完整目录或全部归类 | 依赖少；模型有机会同时比较全局 | 长输入与长输出难核验；失败重做成本高；遗漏、位置偏差和目录/归类相互污染需要专门检查 | 用作小规模对照或全局归并阶段；不作为唯一生产路径 |
| 分片归纳、全局合并 | 各片发现带支持 ID 的概念；汇总去重、拆分混杂概念和归并同义词；统一规划后再逐项归类 | 只需现有聊天模型；可重试、可追溯；适合千条以内 | 分片边界会影响候选；只合并名字可能掩盖不同含义；摘要可能丢细节 | **当前优先**，但必须保留成员证据和全库残差复核 |
| 嵌入聚类、LLM 命名 | 摘要/特征嵌入→聚类→代表及边界样本命名→层级归并 | 大库可减少重复语义比较，方便发现自然聚集 | 中文英文、短标题、通用站点模板和离群资源影响聚类；簇不自动等于可用目录 | 有质量证据或规模需求时再引入；不先部署向量数据库 |
| 迭代目录修订 | 初始树→临时归类→检查大类混杂/未覆盖项→提出有限修订→再归类受影响项 | 可依据真实数据逐步改好，适合新增资源 | 无版本与停止条件时会不断改名、移动和漂移；错误归类可能反过来强化错误目录 | 作为前两条路线的受控闭环；每版目录和批准结果必须分开 |

## 推荐的可落地算法

### A. 全库盘点，建立可靠输入

为每个网站建立稳定资源 ID 和紧凑证据卡：用户改名、导入时原标题、URL、页面用途摘要或可信正文片段、备注、标签、原浏览器目录、采集质量。把登录、挑战、报错等页面标为污染证据；没有充分证据就保留未知，不能靠模型补造网站功能。

Obsidian 参考只提取当前任务需要的目录原则和惯用术语。区分主题目录、项目目录、附件、模板、收件箱；它是用户偏好的先验，不能当作这批书签分类的现成标准答案。旧 AI 建立的目录也不能自动当作人工确认的标签。

### B. 发现候选主题，而非立即输出文件夹操作

按实际 token 预算分片，每条有有效证据的资源至少参与一次；如先用样本提速，必须另做全库未覆盖项扫描。避免只按原目录连续取样，也不要只看最常见域名。固定资源快照、抽样种子和分片记录以便重现。

各分片输出候选名称、含义、收录条件、排除条件、支持资源 ID、边界资源 ID，并将“主题/工作用途”与“文档/工具/社区等形式”分开记录。不在此阶段创建目录或移动网站。单条证据足以报告候选长尾主题，但未必足以决定新建一级目录。

### C. 全局归并，建立层级草案

汇总全部候选，检查全局同义、包含、交叉和不相关关系：同义合并；上位—下位关系形成父子；交叉属性优先转成标签；不同概念不能因名称相近或数量少就合并。保留每次合并的候选映射与支持 ID。

每次命名读取实际成员摘要及易混淆的邻类例子。层级必须满足“子类比父类具体、兄弟节点按同一原则切分”。可以直接归到父目录；不要强迫所有分支同样深，不要求各类网站数量均衡，也不预设只有六个一级目录才合格。

输出目录草案时，附每类范围、代表资源、可能冲突、尚未覆盖项和相较参考目录的变化。此时成员数量若只来自候选发现，应明确为估算或支持样本数，不能伪装成已完成的逐项分类数量。按本轮任务边界，先展示报告，再决定是否运行后续归类。

### D. 固定版本，逐项指派

确认后的目录保存 `taxonomy_version` 与稳定类别 ID。每批使用完全相同的范围规则；只返回合法类别或明确的待人工状态。结果包含资源 ID、主要目标、可选标签、简短依据及实际输入中的证据引用。不得在归类批次中临时新增目录。

分别校验：输入输出 ID 是否完整、不重复；目录 ID/版本是否合法；引用是否真实存在；引用的含义是否确实支持目标。前面三项可确定性检查，最后一项需要抽查或独立判定，不能因字符串匹配通过就宣称语义正确。

### E. 根据残差修订，而非无休止重跑

将未解决项区分为：证据缺失、主用途有歧义、目录缺少合适主题、已有类范围不清。只有后两项直接构成目录修订证据；采集失败不能通过增加“其他”目录解决。

当一个现有类别混杂了多个具有独立检索用途的群体时考虑拆分；多批出现同义分支时合并；出现清晰新领域时扩宽。低频只提示检查，不自动删除。每轮说明受影响的资源 ID、理由和新旧目录映射，仅重新判断受影响部分。达到事先约定的人工可接受质量或预算时停止，剩余问题列为待审核，不能靠反复自评强行宣布合格。

## 最小对照实验与质量目标

实施前不应直接重跑全库并把“文件夹更少”当成功。建议保留同一份冻结资源证据，比较现方案、全库紧凑提示基线、上述分片归纳方案。先选择覆盖常见领域、长尾、跨领域、不同语言和采集异常的样本；样本量可从几十条开始，但覆盖情况和误差都需报告。改变顺序或分片重跑，检查目录语义及逐项结果的变化。

| 评估对象 | 应记录的结果 |
| --- | --- |
| 目录自身 | 同义重复、父子范围错误、兄弟切分原则混杂、无证据支撑的类、缺失主题 |
| 资源归类 | 人工可接受率、明显误放、主领域与细分类错误分别计数；同时报告待人工率 |
| 长尾与边界 | 稀有但重要主题有没有被吞掉；跨领域资源的主归属是否可解释 |
| 检索用途 | 给出真实查找任务，用户是否能预测进入哪个目录；目录名与内容是否相符 |
| 稳定性 | 重排输入/更换分片后路径语义是否稳定；新增少量网站是否无故重排大部分旧资源 |
| 成本 | 实际请求数、输入输出 token、耗时、失败重试数，以及需要人类改动的条目数 |

这些维度分别受上述研究启发，但具体样本、阈值与权重属于本项目待验证的选择。TopicGPT 的 purity、LLooM 的 concept coverage、Clio 的合成对话恢复率、TaxoAdapt 的 LLM 评分衡量不同任务，不能互相当成同一种“准确率”，更不能转为本项目的质量承诺。仅有自动评审时，应标注“模型评审”，不能报告为“人类认可”。

轻量首版可把证据卡、候选概念、目录版本、逐项建议及残差报告保存为 JSON/现有 SQLite 记录，并复用既有模型调用与人工校对能力。是否增加嵌入模型、聚类依赖或独立评分模型，应由同样资源和评价方法下的实测收益决定。
