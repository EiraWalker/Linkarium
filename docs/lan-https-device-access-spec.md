# 可选局域网 HTTPS、网络适配器选择与设置页设备入口

状态：产品决策及测试边界已确认，待实现。本规格不表示功能已经实现或实机验收已经完成。

## Problem Statement

Linkarium 的“添加其他设备”目前按当前服务的来源生成授权链接和二维码。在电脑通过 localhost 打开设置页时，手机扫描得到的 localhost 会指向手机自身，无法访问电脑上的收藏库。

目前局域网 HTTPS 通过独立的本机脚本、附加 Web 进程和代理配置提供，尚未整合到标准启动和设置页。用户需要分别处理地址、CA 证书、网络适配器和设备授权，无法从一次启动及现有设置页面完成连接准备。

普通 HTTP 私网 IP 可以作为网站访问地址，但不满足 Passkey 的安全上下文要求。直接把现有授权链接中的 localhost 替换为私网 IP，会产生能够打开页面却无法完成授权的链接，还会违反现有授权来源和 RP ID 校验。

## Solution

标准启动入口提供可选的局域网 HTTPS 开关，以及可省略的网络适配器选项。优先选择已连接且有可用 IPv4 的物理 Wi-Fi；没有可用 Wi-Fi 时选择物理以太网，自动选择时排除虚拟适配器。明确指定的适配器不可用时启动报错。

普通 HTTP 模式在设置页展示所选适配器 IPv4 和实际端口构成的网站访问链接与二维码；不提供新设备 Passkey 授权，不显示局域网 CA 按钮。本机通过 localhost 使用的既有正常认证能力保留。

启用局域网 HTTPS 时，电脑与手机统一使用配置的 HTTPS 域名。启动终端输出实际 HTTPS 地址、公开 CA 证书的绝对路径和证书安装页地址。设置页只读展示当前连接配置，现有“添加其他设备”的授权链接与二维码使用同一 HTTPS 规范来源。

“安装 CA 证书”按钮位于“生成新的授权”右侧，仅在局域网 HTTPS 模式显示。按钮打开同一局域网内的 HTTP 证书安装页，使尚未信任本地 CA 的手机能够先取得公开证书，再进入 HTTPS 网站完成 Passkey 登记。

既有 HTTPS 域名和 CA 持久复用。Wi-Fi IP 与保存的配置不一致时停止并提示修正，不自动改变域名或重新建立 CA。配置由启动参数及服务器持久配置决定，网页不提供修改或重启开关。

## User Stories

1. 作为本机运行 Linkarium 的用户，我希望默认启动仍可使用普通 HTTP 模式，以便自行决定是否启用局域网 HTTPS。
2. 作为希望连接手机的用户，我希望通过标准启动入口的一个可选开关启用局域网 HTTPS，以便不再单独运行临时 HTTPS 脚本。
3. 作为用户，我希望网络适配器参数可以省略，以便连接常用 Wi-Fi 时直接启动。
4. 作为连接 Wi-Fi 的用户，我希望默认选择已连接且有可用 IPv4 的物理 Wi-Fi，以便生成其他设备可访问的服务器地址。
5. 作为没有可用 Wi-Fi 的用户，我希望自动改用已连接且有可用 IPv4 的物理以太网，以便有线网络也能提供访问入口。
6. 作为安装了代理、VPN 或虚拟机的用户，我希望自动选择排除虚拟适配器，以便不会把虚拟网络地址误当作手机入口。
7. 作为拥有多个网卡的用户，我希望能在启动时明确指定网络适配器，以便使用目标网络。
8. 作为明确指定网卡的用户，我希望网卡不存在、断开或没有可用 IPv4 时得到启动错误，以便发现错误而不被静默切换网络。
9. 作为普通 HTTP 模式的用户，我希望设置页显示所选网卡的 IPv4 和实际端口，以便取得正确的网站访问链接。
10. 作为普通 HTTP 模式的用户，我希望访问二维码解码结果与显示、复制的链接一致，以便扫码和复制通向同一个站点。
11. 作为手机用户，我希望普通 HTTP 页面明确区分网站访问与 Passkey 授权，以便不会把无法完成注册的链接当成设备授权。
12. 作为本机用户，我希望普通模式保留 localhost 的既有登录能力，以便不影响日常电脑使用。
13. 作为启用局域网 HTTPS 的用户，我希望电脑与手机使用同一配置域名，以便授权和登录具有一致的站点身份。
14. 作为服务器操作者，我希望服务就绪后终端显示实际 HTTPS 地址，以便直接打开正确入口。
15. 作为服务器操作者，我希望终端显示公开 CA 证书的绝对路径，以便找到并分发手机需要安装的证书。
16. 作为首次连接的 Android 用户，我希望在尚未信任 CA 时能打开局域网证书安装页，以便先下载证书再进入 HTTPS 网站。
17. 作为设置页用户，我希望看到当前启用的模式、访问地址和所选适配器，以便了解正在运行的连接配置。
18. 作为设置页用户，我希望连接配置是只读状态，以便网页显示始终对应本次启动实际生效的配置。
19. 作为局域网 HTTPS 用户，我希望在“生成新的授权”右侧看到“安装 CA 证书”，以便在配对区域找到手机准备入口。
20. 作为普通 HTTP 模式的用户，我希望页面不显示局域网 CA 安装按钮，以便不会出现不适用于当前模式的操作。
21. 作为已登录的所有者，我希望新设备链接和二维码使用配置的 HTTPS 服务器地址，以便手机能够访问真实服务器。
22. 作为所有者，我希望链接、二维码和复制结果都来自同一后端授权结果，以便它们不会产生来源或令牌差异。
23. 作为新设备用户，我希望继续通过链接与独立授权码创建 Passkey，以便保留现有跨设备加入流程。
24. 作为所有者，我希望二维码和链接不包含独立授权码，以便授权保持现有的两项输入要求。
25. 作为所有者，我希望新设备授权继续五分钟有效、一次成功使用后失效，以便连接配置调整不会扩大授权权限。
26. 作为已安装 CA 的用户，我希望后续启动复用同一 CA，以便不需要反复安装证书。
27. 作为已登记 Passkey 的用户，我希望后续启动复用同一 HTTPS 域名，以便已登记凭据继续适用于同一站点。
28. 作为使用现有本机 HTTPS 配置的用户，我希望正式启动整合能够复用现有域名和 CA，以便不丢失已有设备的信任准备。
29. 作为遇到 Wi-Fi IP 变化的用户，我希望服务明确停止并说明配置不匹配，以便主动修正地址而不是悄悄换一个 Passkey 站点。
30. 作为首次为 HTTPS 域名登记凭据的用户，我希望保留现有所有者、localhost 凭据和文件公钥，以便新增站点入口不等于重置账号。
31. 作为收藏库所有者，我希望连接配置变化不修改网站收藏、收藏文件夹、标签、备注或页面快照，以便网络配置与业务数据分开。
32. 作为服务器操作者，我希望 HTTPS 依赖、证书、绑定地址或端口异常时启动明确失败，以便不会误以为 HTTPS 已经可用。
33. 作为服务器操作者，我希望启用该功能仍只有一个正常采集 worker，以便不会重复执行后台任务。
34. 作为手机用户，我希望配对区域在手机尺寸下仍能访问两个按钮、二维码及授权码，以便完整操作设备加入流程。
35. 作为维护者，我希望使用隔离数据与测试凭据验证 HTTP 和 HTTPS 两种模式，以便不改变日常收藏库或真实授权。
36. 作为用户，我希望验收记录区分自动化协议验证与真实 Android 验证，以便清楚知道手机连接是否实际通过。

## Implementation Decisions

以下产品行为来自已确认的 Q1–Q6。模块划分、契约语义和验收组织是基于现有实现补齐的技术约定；不扩展账号体系或改变既有授权规则。

### 1. 启动与生命周期

- 在标准启动流程整合可选局域网 HTTPS 模式及可选适配器参数。默认不启用局域网 HTTPS；参数须有帮助说明，并与既有端口、采集及认证选项保持兼容。
- 启动控制层统一解析连接配置、启动 Web 和需要的 HTTPS 代理／证书安装页，并管理它们的就绪和退出。正式运行不再依赖另起一个附加业务 Web 进程；保留单 supervisor、单正常 worker 的运行约束。
- 启动成功信息只在对应入口就绪后输出。HTTPS 模式输出规范 HTTPS 地址、公开 CA 证书绝对路径及证书安装页地址；不得把 CA 私钥或服务端私钥作为分发路径输出。
- 校验适配器、IPv4、端口、HTTPS 依赖、证书和持久配置。依赖缺失或配置错误应给出可执行的修正信息，不静默降级成 HTTP、不改变已固定的来源或端口。
- 沿用已有安装准备流程和版本校验惯例准备 HTTPS 运行依赖，不把静默安装系统服务、修改全局证书信任或关闭防火墙作为启动成功条件。

### 2. 适配器选择与实际地址

- 显式指定优先于自动选择。指定对象必须存在、已连接且有可用 IPv4；失败直接报错，不改用其他网卡。
- 自动选择优先物理 Wi-Fi，其次物理以太网；排除代理、VPN、虚拟机及其他虚拟适配器，排除 loopback、未连接、无 IPv4 和链路本地自动配置地址。
- 同一优先级出现多个候选或同一网卡存在多个无法唯一选定的 IPv4 时，列出可用候选并要求明确指定；不任意取系统枚举的第一项。
- 普通 HTTP 模式的对外访问地址由选定 IPv4 与实际监听端口生成；端口自动选择后必须传播实际端口，显式端口被占用则保留现有固定端口失败语义。
- Web 监听须覆盖所选适配器的访问入口，同时保留普通模式的本机 localhost 认证入口。设置页不能公布一个实际未监听的 IP 地址。

### 3. 运行配置与设置页契约

- 服务器统一持有本次运行的连接配置，区分网站访问地址与 Passkey 规范来源；普通 HTTP 的私网访问地址不能被当作有效 Passkey RP ID 或授权来源。
- 已登录的设置页通过服务端运行状态获得当前模式、所选适配器、IPv4、实际访问地址及适用时的 CA 安装页地址。前端不从浏览器的 location、未经验证的 Host 或转发头推断对外授权目标。
- 设置页只读展示连接信息，不提供启用、地址编辑、证书重建或服务重启操作。启用与配置变更由启动参数及服务器持久配置决定。
- 运行状态不返回 CA 私钥、TLS 私钥、真实授权码或其他认证秘密。CA 的服务器绝对路径供启动终端使用，网页提供可访问的公开证书安装入口。

### 4. 普通 HTTP 模式

- 配对区域在该模式展示“网站访问”语义的 IP＋端口链接、复制操作及二维码。二维码由前端本地生成，与显示和复制结果一致；该地址不含授权令牌或授权码。
- 不生成和展示新设备 Passkey 授权，不显示新设备授权码、有效期或“生成新的授权”，不显示“安装 CA 证书”按钮。后端同时拒绝不适用的新设备授权操作，不能仅在前端隐藏。
- 以一条必要状态说明 HTTP 访问入口不支持新设备 Passkey 授权，启用 HTTPS 后才能使用。普通模式下的 localhost Passkey 与既有可选文件密钥登录能力保留。
- 本项不新增 HTTP 密码登录、令牌直接登录、浏览器安全策略例外或其他替代认证方式。

### 5. 局域网 HTTPS 与 CA

- 电脑、手机及设置页设备加入流程统一使用固定 HTTPS 域名；原始 IP 不作为 Passkey RP ID。沿用现有规范来源、RP ID、Origin、CSRF 和 challenge 校验。
- 既有域名和 CA 应有明确的复用接管方式。后续启动继续使用同一身份；服务端叶证书可在同一 CA 和域名下正常续签。
- 只有尚无可复用 CA 的首次准备才创建新的 CA。CA 和相关私钥作为服务器持久运行资料保存，不进入前端构建、公开下载目录、普通收藏库导出或版本库。
- 所选 IPv4 与已保存的域名／绑定配置不一致时明确失败，提示修正网络或配置。禁止自动换域名、重建 CA 或宣称旧域名 Passkey 已迁移。
- 保留局域网 HTTP 证书安装页，提供公开 CA 证书下载及 Android 安装步骤。该页不提供登录、授权码、授权令牌、认证状态库或任何私钥。
- 证书安装页只在局域网 HTTPS 模式随服务提供；关闭该模式后不继续作为遗留进程运行。其地址与应用 HTTPS 地址分别标识，不把安装页二维码当作设备授权二维码。
- 网络暴露限定为所选适配器及需要的服务端口，代理上游和管理接口保持本机限制。防火墙放行限定所选适配器及本地子网；需管理员操作时明确报告步骤，不把尚未放行当作手机可连接证据。

### 6. 设备授权及按钮位置

- HTTPS 模式下，新设备授权记录中的 origin、RP ID、返回的添加链接、二维码内容和最终注册验证必须一致。不能只在前端替换 localhost，不能为此放宽来源校验。
- 二维码、链接输入框和复制操作使用同一个后端 enrollment URL。授权码保持独立，不能加入 QR 内容或链接。
- 沿用新设备授权五分钟有效、单次成功消费，以及现有错误码、错配、过期、重放、并发提交和凭据管理行为。
- 在既有“生成新的授权”按钮右侧增加“安装 CA 证书”。它打开配置的证书安装页；不替换授权二维码，不签发新的授权，不撤销现有授权。
- CA 按钮只在局域网 HTTPS 模式显示；在桌面尺寸遵循用户指定的右侧位置，窄屏允许自然换行并保持先生成授权、后安装证书的顺序。
- 用户从旧 localhost 入口进入 HTTPS 模式的认证或设置操作时，应引导到已配置的规范 HTTPS 地址后继续，不签发来源不匹配的授权。

### 7. 数据与凭据兼容

- 连接配置属于服务器运行配置，不是收藏库内容或可恢复的业务配置；不要求改变网站收藏的数据结构。
- 复用现有 owner、Passkey、文件公钥和业务数据库。为 HTTPS 域名首次登记凭据走现有授权流程，不调用重置、删除旧凭据或替换所有者。
- localhost 的 Passkey 不自动变成 HTTPS 域名的 Passkey。两种来源之间的既有凭据和浏览器会话差异需要按现有认证规则处理。
- 模式切换不改变授权用途、成功消费次数、十四天会话期限或删除凭据的既有约束；不通过改写数据库记录伪造迁移。

## Testing Decisions

已确认的测试边界：以一次公开启动到浏览器设备加入的完整链路为主要验收边界，复用现有隔离认证验收与 supervisor 进程测试。

### 主要验收边界

- 使用隔离数据目录、正式构建的前端、真实 Web／HTTPS 服务及独立浏览器上下文，从启动参数和终端输出开始，经设置页、二维码解码、证书安装页、授权签发，到独立浏览器的新 Passkey 注册与登录结束。
- 复用现有认证 UI 验收的隔离服务、二维码像素解码、独立上下文和 WebAuthn 虚拟认证器；复用启动验收中控制子进程、检查实际端口及终端输出的方式。
- 好的测试断言实际 URL、QR 内容、可见状态、按钮能力、响应、证书验证及受保护收藏库是否可访问；不把内部 helper、组件名称或调用次数作为通过条件。
- 适配器枚举是环境输入。只在操作系统网卡发现边界提供可控候选集合，覆盖有线、无线、虚拟、断开、无 IPv4 和多个候选；不用新增测试专用公开 API，也不改动测试主机实际网卡或默认路由。
- 保留现有后端认证集成测试，重点回归来源、RP ID、授权错配和过期；优先在已有验收边界补场景，不在多个内部模块重复验证同一行为。

### 必须通过的自动化场景

| 编号 | 场景与通过条件 |
| --- | --- |
| A01 | 不启用 HTTPS 时保持普通模式；本机 localhost 的既有正常登录仍可使用。 |
| A02 | 存在可用物理 Wi-Fi 和多种虚拟网卡时选择 Wi-Fi，终端与设置页报告同一 IPv4。 |
| A03 | 无可用 Wi-Fi、有物理以太网时选择以太网；只有虚拟网卡或无有效候选时明确失败。 |
| A04 | 显式适配器覆盖自动选择；不存在、断开或无可用 IPv4 时失败，不能静默改用其他适配器。 |
| A05 | 多候选歧义需明确指定；端口自动选择后的实际端口在访问地址、二维码和运行状态中一致。 |
| A06 | 普通模式 QR 解码值、输入框和复制值均为选定 IPv4＋实际端口的网站入口，实际请求可达。 |
| A07 | 普通模式无设备授权码、到期计时、重新签授权和 CA 安装按钮；直接请求新设备授权也被拒绝。 |
| A08 | HTTPS 启动完成后终端输出真实可访问的规范 HTTPS 地址、存在的公开 CA 证书绝对路径及安装页地址。 |
| A09 | 设置页只读显示实际启动配置；前端不随当前 Host 或伪造转发头切换发布地址。 |
| A10 | HTTPS 页面通过配置的 CA 验证域名与证书链，浏览器处于安全上下文，API 报告 Passkey 可用。 |
| A11 | 设备授权链接、二维码、复制结果、授权 origin 与 RP ID 对应同一规范 HTTPS 域名，均不回退 localhost。 |
| A12 | 独立浏览器用链接＋授权码经虚拟认证器完成注册和登录，可访问受保护收藏库；原凭据保留。 |
| A13 | 二维码不含独立授权码；错配来源、错误 RP ID、CSRF、过期、重放及并发消费继续按原规则被拒绝。 |
| A14 | HTTPS 模式下 CA 按钮位于生成授权按钮之后、桌面呈右侧布局；打开正确证书安装页且不新签或撤销授权。 |
| A15 | 证书安装页能下载与服务器 CA 相同的公开证书；私钥、状态数据库、授权信息及下载目录外内容不可取得。 |
| A16 | 同一配置重启后规范域名和 CA 指纹保持不变，已登记 HTTPS Passkey 可再次登录。 |
| A17 | 在隔离环境复用已有 CA 和域名配置成功，不生成替代身份；首次 HTTPS 登记不重置原 owner 或凭据。 |
| A18 | 保存的 IPv4／绑定配置不匹配、端口占用、依赖缺失或证书不可用时明确失败，不降级 HTTP。 |
| A19 | 启停 HTTPS 模式无重复 worker、无遗留证书安装页或代理进程，不操作同机其他服务。 |
| A20 | 桌面与手机视口的按钮、链接、二维码、授权码和错误状态均可操作；普通模式与 HTTPS 模式能力一致地切换。 |
| A21 | 隔离样例的收藏、文件夹、标签、备注、页面快照和既有凭据在启用、重启和关闭模式后保持完整。 |

### 实机验收

- 在同一 Wi-Fi 的真实 Android 设备上打开证书安装页，安装并信任公开 CA，再使用配置的 HTTPS 域名访问设置和登录页面。
- 从电脑设置页生成授权，通过手机扫码、另行输入授权码、创建 Passkey、退出并再次登录，证明完整流程实际可用。
- 在同一域名和 CA 下重启服务，再验证手机登录；记录设备、系统、浏览器、认证器、适配器类型、访问来源及结果。
- 虚拟认证器、浏览器临时信任、手机视口、本机访问网卡 IP 或单独健康检查均不能代替 Android 的系统证书安装和真实 Passkey 验收。没有实机证据时该项保持待验证。
- 测试使用隔离收藏库、测试授权及测试凭据；不重置日常账号、不修改日常网卡，不发布真实授权码、令牌、证书私钥或个人收藏截图。

## Out of Scope

- 普通 HTTP 私网 IP 上的 Passkey 注册／登录，以及为此绕过浏览器安全上下文或削弱服务器来源校验。
- 新增 HTTP 密码登录、扫码即登录、匿名公开注册、多用户账号或其他替代认证协议。
- 在设置页修改连接配置、切换 HTTPS、重建 CA、重启服务或管理网络适配器。
- 公网域名、公共 CA、DNS 提供商、CDN、路由器端口映射、跨互联网部署和 Tailscale 接入。
- 自动修改路由器 DHCP、自动修正 IP 变化、自动更换 Passkey RP 域名或自动迁移域名凭据。
- 自动替手机安装证书或操作手机认证器，静默修改系统全局信任、关闭防火墙或停止其他程序。
- 新的 IPv6、多网卡同时对外服务方案或浏览器会话跨域共享。
- 改写采集、分类、页面快照、导入、备份或恢复的业务语义，以及本次规格编写中的代码实施、提交、推送或部署。

## Further Notes

- 本规格补充既有 [Passkey 首次初始化与跨设备登录 Issue #4](https://github.com/EiraWalker/Linkarium/issues/4)，不替代其凭据生命周期与尚待完成的实机验收。
