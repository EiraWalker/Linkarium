# Linkarium 全部 AI 分类改由发起设备执行

日期：2026-10-21。状态：已实现并完成隔离环境验收，生产部署与用户配置升级待后续验收，记录见 `docs/local-ai-implementation.md`。当前代码基线：`c4eb9531e1166603e7e723d04edee24c4435a4c7`。

本规格来自本轮 grilling 访谈，覆盖全部分类入口，后续替代 Issue #8 中由云端调用模型的部分。Firefox 一键收藏、去重、分类校对和范围受限的插件自动归档规则继续保留。

## Problem Statement

用户希望 Linkarium 继续保存和管理云端收藏，但所有 AI 分类都由任务发起设备调用自己的 OpenAI 兼容 API。当前实现由服务器 worker 读取服务器 AI 配置和密钥并调用模型；把线上接口地址设置为本机回环地址，只会访问服务器自身，不能使用用户电脑上的 API。

用户不希望为此安装额外后台助手，也不希望服务器或其他设备替发起设备执行分类。Firefox 关闭、API 断连或执行意外中断时，分类需要像下载任务一样保留进度、暂停并恢复。现有服务器批次级恢复可以复用，但尚未覆盖模型已返回本机、云端尚未确认的中断窗口。

## Solution

云端负责保存收藏、获取分类材料、生成完整 prompt、管理任务和校验归档；已有 Firefox 插件成为发起设备的本机 AI 执行端。插件使用该设备配置的 API 地址、密钥和模型调用 OpenAI 兼容服务，将完整结果可靠地回传云端。

网页新增、手动分类／重分类、文件夹／选中项／全库分类、HTML 导入、插件收藏及共享分类体系规划，全部使用这条链路。任务绑定发起设备，不进入其他设备可领取的公共执行池，不提供手动转交功能。

执行顺序为：发起并绑定设备、云端准备 prompt、该设备领取批次、本机调用模型、本机保存完整结果、幂等回传、云端校验并保存方案，最后按入口既有策略进行人工校对或插件自动归档。

已完成批次和共享分类体系继续复用。中断后，已有完整本机结果优先重传；尚未获得完整结果的调用恢复后重新请求该批。云端接受收藏、模型完成响应、生成有效方案和实际归档是不同结果，界面分别显示。

## User Stories

1. 作为收藏库所有者，我希望所有分类入口都由发起设备调用模型，以便服务器不再代我执行模型请求。
2. 作为 Firefox 用户，我希望复用已安装的插件执行分类，以便不必安装额外后台助手。
3. 作为使用本机 API 网关的用户，我希望配置 OpenAI 兼容接口，以便使用该设备已有的模型服务。
4. 作为多设备用户，我希望每台设备分别配置地址、密钥和模型，以便自行解决各设备的 API 可用性。
5. 作为所有者，我希望模型密钥只保存在对应设备，以便云端和其他设备不会取得它。
6. 作为插件收藏用户，我希望点击按钮后先保存当前网址和标题，以便分类尚未完成时收藏也不会丢失。
7. 作为网页用户，我希望新增网页所需的分类也走本机执行端，以便不再依赖服务器模型配置。
8. 作为整理收藏的用户，我希望选中项、文件夹、全库分类及重分类使用同一执行链路，以便行为一致。
9. 作为导入用户，我希望 HTML 导入的分类批次由发起设备执行，以便导入同样能使用本机 API。
10. 作为已有管理入口的用户，我希望其触发的分类也遵守设备绑定，以便没有隐藏的服务器模型调用分支。
11. 作为所有者，我希望共享分类体系规划同样由本机模型完成，以便分类的前置规划也符合本地调用要求。
12. 作为用户，我希望云端下发完整 prompt，以便不同入口复用相同的分类规则和目录约束。
13. 作为任务发起者，我希望任务一直绑定发起设备，以便其他设备不会使用自己的模型或密钥接管我的工作。
14. 作为多设备用户，我希望其他设备可以查看任务进度，以便了解状态而不会改变执行责任。
15. 作为任务发起者，我希望 Firefox 退出时任务暂停，以便重新打开后可以继续未完成的工作。
16. 作为用户，我希望插件后台被卸载或重启时保留任务身份，以便后台生命周期不会造成进度丢失。
17. 作为 API 暂时不可用的用户，我希望分类暂停并说明原因，以便修复连通性后继续处理。
18. 作为离线用户，我希望已经保存的云端收藏继续可见，以便本机执行端离线不会被误认为收藏保存失败。
19. 作为批量分类用户，我希望已完成批次不因后续中断全部重做，以便保留已取得的成果。
20. 作为用户，我希望模型完整结果先在本机保存，以便回传云端失败时无需再次请求模型。
21. 作为用户，我希望云端已接收但确认响应丢失时能够查询原结果，以便不会重复生成方案或重复归档。
22. 作为任务发起者，我希望尚未收到完整结果的批次恢复后重发，以便中断调用不会被错误标为成功。
23. 作为用户，我希望恢复进度以批次为单位，以便清楚知道哪些已完成、哪些需要重新调用。
24. 作为已登录用户，我希望继续复用 Linkarium 登录和 CSRF 校验，以便不必另建云端集成密码。
25. 作为会话过期的用户，我希望重新登录后继续原设备的任务，以便不需要重新创建收藏和整个分类批次。
26. 作为人工整理目录的用户，我希望迟到结果不能覆盖新的手动修改，以便已完成的整理受到保护。
27. 作为所有者，我希望取消、替代分类、清空或恢复收藏库后旧响应失效，以便旧任务不会写入新的收藏库状态。
28. 作为网页和导入用户，我希望本机生成的分类方案仍可校对，以便执行位置变化不会取消人工审批。
29. 作为插件收藏用户，我希望本入口新建收藏仍可自动归档，以便保留一键收藏的既有体验。
30. 作为重复收藏用户，我希望已有记录不因新执行链路被重分类，以便原目录、备注和星标等人工信息保留。
31. 作为用户，我希望元数据或快照失败时仍能按既有规则使用网址和标题分类，以便非模型任务不会永久阻塞工作。
32. 作为用户，我希望明确看到等待本机、等待配置、执行中、等待回传和最终结果，以便不会把模型完成当作已归档。
33. 作为使用不同模型的用户，我希望先验证实际结构化响应能力，以便仅能列出模型的接口不会被误认为可以分类。
34. 作为用户，我希望无效 JSON、未知网站或越界目录结果被拒绝，以便模型返回不能直接修改收藏库。
35. 作为用户，我希望本机配置变化不会混用旧密钥和新服务地址，以便模型请求始终使用明确选择的配置。
36. 作为备份用户，我希望业务备份不包含各设备 API 密钥，以便恢复收藏不会复制设备凭据或重启旧执行权限。
37. 作为已有实例的用户，我希望升级保留收藏、快照、登录凭据和已有待校对方案，以便切换执行位置不损坏现有数据。
38. 作为旧插件用户，我希望协议不匹配时得到明确升级提示，以便不会一直看到接口错误或被悄悄退回云端调用。
39. 作为用户，我希望原设备无法恢复时能够取消旧任务并重新发起，以便不需要实现任务转交也能继续工作。
40. 作为验收者，我希望真实 Firefox 的完整操作链路经过验证，以便接口和构建通过能够对应到实际可用功能。

## Implementation Decisions

### 1. 已确认的执行边界

- “本地”表示请求由用户设备上的 Firefox 插件发出，不要求模型权重或推理也在该设备。允许本机网关转发上游模型，不将该方案描述为离线推理。
- 不新增 Windows 服务、桌面助手、Native Messaging 程序或由云端访问用户电脑的网络通道；各设备自行准备 API、密钥和连通性。
- 所有分类相关模型调用都迁到本机，包括共享分类体系规划。服务器 worker 继续处理元数据、快照、任务编排和业务事务，但不得再消费本机 AI 批次并调用模型，也不得在本机离线时回退云端调用。
- 云端继续获取有界网页材料并生成完整 prompt。本机不得根据任意网页消息自行获取整库、另建提示词策略或扩大分类范围。
- 当前适配目标沿用 Firefox 桌面版及 Nightly。任务来自其他设备时，仍须具备本方案支持的本机执行端；不由服务器代为解决设备 API 配置或浏览器适配。

### 2. 设备身份和发起责任

- 为 Firefox 配置文件中的本机执行端建立持久、不透明的设备标识，通过当前 owner 登录会话登记。设备标识用于路由和责任绑定，不能代替身份认证；不以 IP、API 地址或模型名称推断设备身份。
- 分类启动请求在入队时记录发起设备。网页和插件入口在同一浏览器中完成受限的设备绑定；管理入口也须提供有效绑定，不能省略后默认选择当前在线设备。
- 只有发起设备可领取、续约、恢复和回传该任务的本机执行结果。另一台设备即使登录同一账号且 API 可用，也不能领取或接管；不提供手动转交接口或界面。
- 缺失可验证设备绑定时，分类启动明确返回需要绑定本机执行端的状态，不创建可被任意设备领取的无主任务。设备已绑定但 API 或插件暂未就绪时，任务可等待该设备；收藏保存与分类执行分开处理。
- 同设备多标签页、多窗口和后台重唤醒不能形成重复执行器。工程默认每设备串行执行一个模型调用，继续复用服务器任务批次和尝试记录，不再建立独立分类调度系统。
- 设备重新安装或丢失本地身份，不把新身份隐式视为旧设备，也不自动接管旧任务；可取消旧任务并在当前设备重新发起。其他设备查询进度不改变归属。

### 3. 云端 prompt 与本机模型配置

- 拆分现有分类中的准备、模型传输、结果校验与提交职责。云端沿用现有材料预算、共享目录、分类范围、候选目录和输出约束，生成完整消息及结构化输出要求；本机只负责使用本地配置执行相应模型请求并可靠回传。
- 每次调用区分共享分类体系规划和网站归类，绑定任务／阶段／批次、收藏库 generation 与 epoch、prompt 版本及摘要、网站分类版本、目录版本和共享分类体系版本。已领取尝试使用固定输入快照。
- 每设备独立保存 API 地址、密钥、模型、兼容输出模式及验证状态；不上传云端，不使用浏览器配置同步，也不进入业务备份。模型由本机选择，云端不统一指定具体型号。
- 不再以服务器活动 AIProfile 是否启用、是否有 ProviderSecret 作为本机分类的执行前提。原服务器配置只作历史兼容，不继续调用，不下发既有秘密，也不在本次迁移中自动删除或复制旧凭据。
- 以现有 OpenAI 风格 Chat Completions 非流式能力作为兼容基线。配置验证须覆盖实际模型响应、JSON 输出模式和参数支持，仅有模型列表或 CORS 预检成功不足以判定兼容。
- 地址、协议或模型变化需重新验证相应能力；不能让旧密钥自动跟随未经确认的新来源。执行中的尝试记录其配置快照，后续尝试才使用新配置。
- 延续现有输入与资源预算：网站归类每批最多 10 个网站，普通分类和共享规划分别采用现有 120 秒与 240 秒预算；保留有限正文、总输入、响应体、输出结构和目录数量／层级约束。变更必须有兼容性依据，不能为慢模型取消所有限额。

### 4. 浏览器通信与权限

- 扩展后台执行对本机 API 的请求；内容脚本不直接承担跨域模型调用，也不接收本机 API key。仅按配置来源申请所需权限，不默认申请所有网站访问。
- 云端通信继续复用固定 Linkarium 站点的 owner 会话与 CSRF 同源桥，不复制 HttpOnly Cookie，不新增网站密码存储，不把云端密钥配置表当作本地密钥分发接口。
- 因网页入口也需绑定设备，可增加固定站点的受限消息交互，但只支持设备绑定、已登记任务唤醒及状态等固定操作。校验扩展身份、精确站点来源、顶层页面和消息结构；不得成为网页可调用的任意 URL、请求头、模型请求或脚本代理。
- 本机模型请求只发往当前已验证配置，不跟随重定向泄露密钥，不执行模型提供的工具或代码，不修改用户全局代理和浏览器偏好。默认支持回环 HTTP 或 HTTPS；继续保留对不安全非回环明文端点的既有保护。
- Linkarium 业务页面关闭不等于任务取消。需要云端通信时可复用或恢复后台会话桥；不要求用户持续保持可见页面。会话过期则等待发起设备完成登录，不借用其他设备会话。
- Firefox MV3 后台可被卸载，不能靠内存队列保证执行。领取、调用开始、完整结果保存及云端确认均需可恢复记录；不会将保持一个 Promise 或定时器描述为永久后台保障。

### 5. 批次恢复与本机结果缓存

- 复用已有任务组、每批任务、执行尝试、租约、共享分类体系缓存和已保存分类方案。已有完整阶段记录应成为恢复检查点，不能因后续阶段中断而再次调用模型。
- 增加本机执行阶段的等待、暂停和恢复语义。Firefox 退出、后台被回收、API 断连、云端断连或会话过期时保留进度；恢复运行条件后，由原设备继续。用户主动取消、任务被替代或业务身份失效时不得自动续跑。
- 服务器不能继续沿用“租约过期就交给任意 worker／设备”的处理方式。过期尝试失效并转为等待原设备恢复；恢复重新取得有效授权，不把旧租约重新变为有效。
- 模型完整结果返回后，插件先将有界原始响应和关联任务上下文持久保存为待回传记录，再向云端提交。仅在收到可靠确认或查询证实已处理后清理；不能只把原始结果保存在内存。
- 回传失败优先重传完整缓存，不重复调用模型。服务器已处理但确认丢失时，以同一幂等键或任务结果查询确认既有结论；同键不同结果必须冲突，不能覆盖。
- 原租约过期后，仅由原设备通过恢复协议取得当前授权；在任务、prompt 摘要、库身份和相关版本仍一致时，可在当前授权下提交已有完整缓存。该规则不能成为接受任意迟到旧尝试结果的后门。
- 尚未获得并持久保存完整响应的调用不承诺从中间 token 续传；恢复时重新请求未完成批次。已失败或被拒绝的缓存结果不循环重传为成功，重新推理须进入受控的新尝试。
- 本机缓存有界，只保存执行与恢复所需材料；确认、取消或判定永久失效后可清理相应记录。不能为腾空间静默丢弃仍待回传的结果，应暂停并给出可理解状态。

### 6. 云端执行协议与结果权威

- 在现有认证 API 中增加设备登记／状态、属于本机的任务领取、续约、暂停／恢复、结果提交和结果确认语义。操作均校验 owner、当前设备归属、任务尝试与库身份；写入继续执行 CSRF 和幂等保护。
- 领取响应只返回该设备被授权执行的完整 prompt、输入版本和输出要求，不返回任何设备或服务器 API key。结果提交绑定任务、阶段、批次、有效尝试、prompt 摘要及结果摘要；不能自行扩大网站列表或改写执行策略。
- 本机响应始终作为不可信模型输出。服务器复用严格 JSON、重复键、网站 ID、目录目标、共享分类范围、大小预算和版本校验，不相信浏览器声称的“已验证”或“已归档”。
- 结果接受、阶段完成检查点与相应业务提交保持原子一致，补齐现有通用分类中“方案已保存但任务尚未完成”的崩溃窗口。恢复应识别已提交阶段，而不是再次请求模型。
- 两次完成同一尝试、重复结果回传、确认响应丢失和多个标签页并发均只能产生一次有效业务结果。任务组成员、网站数和批次数沿用现有去重语义，重试不重复计数。
- 人工移动收藏、编辑目录、替代分类、取消任务、清理或恢复收藏库后，旧 prompt 或结果不能覆盖新状态。失效原因需可查询；不通过放宽版本检查或盲目重基解决冲突。
- 共享分类体系的 prompt 生成和校验仍在云端，模型请求在需要它的发起设备执行。完成后在云端持久复用；并发规划需协调和版本保护，不能每台设备各建一套互不兼容的全库目录，也不能把已绑定的规划任务转交另一设备。

### 7. 保留各入口的应用策略

- Firefox 工具栏新建收藏继续采用已有插件自动归档授权；重复网址保留原收藏，不自动重新分类。原始 URL／标题、收藏星标、幂等提交与已有人工字段保护继续有效。
- 有效本机分类结果经云端校验后，插件策略可继续自动应用；目录变更、方案状态、提交终态和任务完成保持既有事务边界。人工修改或替代任务撤销自动应用权限的保护继续有效。
- 网页新增、手动分类、重分类、HTML 导入和既有管理入口继续生成待校对方案，不因改为本机模型调用而自动确认全库分类。人工可修改、确认或驳回，确认后才创建实际目录并改变归属。
- 元数据和快照仍按既有云端规则执行，模型迁移不等于迁移网页采集。信息不足时保留既有 URL／标题回退及说明；已有快照、收藏管理和人工整理不依赖本机 API 在线。

### 8. 状态与用户交互

- 复用网页后台任务入口和插件状态页，显示发起设备、本机执行准备情况、已完成网站与批次、当前阶段及暂停原因；其他设备只查看，不显示转交操作。
- 至少能区分等待发起设备、等待本机配置／登录、执行中、已取得本机结果待回传、已生成待校对方案、已自动归档、失败、取消及结果失效。显示文案不能将本机响应成功等同于归档成功。
- 设备设置提供 API 地址、密钥、模型与兼容性验证；网页可展示当前浏览器执行端状态和打开配置入口，但不读取或保存密钥。缺少本机权限时提供明确授权操作，不静默扩大权限。
- 用户按现有入口恢复或取消任务；已完成批次保留，未完成批次按原设备责任恢复。新的批量任务不能因旧任务暂停而无限重试、清空已完成记录或自动分配其他设备。
- 任务与插件协议版本不匹配时明确提示升级或配置执行端。既有收藏已保存时如实显示，不将兼容问题描述为收藏丢失，也不回退服务器模型调用。

### 9. 数据布局、迁移和交付边界

- 本机 API 配置、密钥、完整响应缓存保存在各自 Firefox 配置文件；设备登记等运行身份与可迁移业务状态保持现有隔离，不引入跨数据库外键。业务任务记录设备不透明标识、输入快照和检查点，不保存本机秘密。
- 业务备份不复制设备密钥。恢复或库 epoch 切换使旧执行授权和旧缓存失效；不能恢复后自动调用旧任务、把旧设备凭据绑定到新库或重放旧响应。
- 迁移保留收藏、目录、快照、登录、历史分类及已完成检查点。旧版未完成且没有发起设备的 AI 任务明确标为需要重新发起，保留历史与已有方案；不得暗中归给部署机器、首台在线设备或继续云端推理。
- 任何新增业务 schema 必须加入受信旧版恢复路径，并用独立于该受信列表的最新实际迁移构造验收目标，防止同时漏更新而误报兼容。
- 后续实现需更新相关 API 契约、状态说明和架构决策，明确替代旧方案的云端模型传输及服务器 ProviderSecret 前提，保留认证隔离和入口审批边界。
- 后端与插件需协调升级并验证实际安装副本、版本、权限与运行状态。本规格不承诺旧版插件自动具备本机权限或本机执行能力。

## Testing Decisions

- 用户已确认主要验收边界为真实 Firefox 的完整链路：“发起分类 → 插件调用本机 API → 云端接收结果 → 校对或自动归档”，并在同一链路验证暂停恢复、重复回传和设备归属。优先扩展这一现有最高层验收，不按每个私有函数新增测试边界。
- 好测试检查外部可见行为：模型请求由哪台设备发出、云端是否保存、进度是否保留、实际生成多少方案、是否需要人工确认、最终归属及错误状态。不得用私有函数调用次数或重写实现逻辑来替代验收。
- 主要环境使用隔离云端实例、真实 Firefox 插件、真实登录／CSRF、真实持久队列和目录事务；外部模型使用只监听测试设备回环的可控 OpenAI 兼容服务。云端不能访问该回环服务，必须由插件完成请求，才能证明调用位置发生变化。
- 既有 Firefox 原生按钮与状态页验收、分类 HTTP 集成、方案确认／幂等、任务重试／过期结果、HTML 导入和旧备份恢复测试作为 prior art；按原接口保留必要回归，不建立另一套只模拟插件返回成功的分类引擎。
- 入口覆盖：插件收藏、网页新增、选中／文件夹／全库及手动重分类、HTML 导入、绑定设备的管理请求；首次共享分类体系规划也必须观察到本机请求。服务器无 AI 密钥、历史 AIProfile 禁用时，已验证本机配置仍可工作。
- 策略覆盖：插件新建收藏自动归档且不遗留同一待校对方案；网页与导入结果必须人工确认；重复网址保留现有记录；人工字段、目录与已有快照保持不变。
- 设备覆盖：至少两个隔离 Firefox 配置文件代表两个设备，各自模型配置独立。设备 B 不能领取、续约或提交设备 A 的任务；设备 A 离线时不转交 B；缺失或伪造设备绑定不能产生可被其他设备执行的任务。
- 恢复覆盖：关闭业务页面、卸载并唤醒插件后台、退出并重新打开 Firefox、本机 API 断连、云端断连和会话失效后，已完成批次与共享规划保留；仅原设备恢复未完成工作，不按整个任务重新开始。
- 中断窗口覆盖：领取后未调用模型、模型尚未返回完整响应、完整结果已持久保存但未回传、服务器已接受但客户端未收到确认。分别验证重新领取／重发未完成请求、缓存重传、原结果查询确认，不能笼统只测试重启后返回成功。
- 原子性覆盖：保存方案与阶段结束之间、自动归档与任务完成之间注入故障；恢复不得重复生成可见方案、重复创建目录或重复移动收藏。已确认结果的再次提交保持相同业务结论。
- 租约与版本覆盖：旧尝试令牌失效；原设备恢复获取新授权后，只在输入快照未变化时接受缓存；取消、替代任务、目录或收藏修改、generation／epoch 切换后旧结果一律不能应用。
- 输入与配置覆盖：JSON／网站／目录／词表越界、超时、过大响应、API 鉴权失败、参数或结构化输出模式不兼容、权限拒绝、地址或模型变化。拒绝结果不能创建目录或将任务标为已归档；配置问题如实暂停并说明。
- 凭据边界覆盖：云端请求、数据库业务备份、网页消息、界面和日志不包含本机 API key；页面不能通过消息桥发任意模型请求或将密钥发送到重定向来源。使用无真实秘密的测试凭据核验，报告必须脱敏。
- 迁移覆盖：从当前线上版本升级并验证身份与业务摘要；所有受支持旧备份恢复到实际最新 schema；旧未绑定任务有明确状态；设备设置和旧执行授权不随业务恢复重放。
- 交付覆盖：后端部署版本、插件实际安装版本及新增来源权限一致，保存旧插件本地状态，确认真实 Firefox 可访问配置来源。构建通过、OPTIONS 成功或模型列表可达均不能代替真实分类请求。
- 可控模型服务验证流程和资源边界，不代表真实模型质量。实际设备上须另行进行有界的真实 OpenAI 兼容分类与结果校对验收；本次撰写规格不执行付费推理或改动生产收藏。

## Out of Scope

- 安装额外本机后台服务、桌面助手、Native Messaging 程序；Firefox 完全退出后仍继续执行模型调用。
- 服务器推理、服务器调用用户模型 API、远程访问用户电脑，以及本机故障时回退云端模型。
- 公共设备抢任务、自动接管、手动转交任务、跨设备同步 API key 或本机模型配置。
- 下载模型权重、部署离线推理引擎、代用户获取密钥、启停其 API 网关或更改全局网络设置。
- 模型生成中间 token 的续传、保证上游模型请求在所有崩溃窗口严格只发生一次、无完整响应时保证不重复计费。
- 将全部分类自动确认、扩大插件自动归档权限、定时全库重分类或覆盖人工整理。
- Firefox 书签库同步、离线新增收藏批量队列、迁移网页采集到本机、上传来源网页 DOM／Cookie／登录态。
- 新增 Chrome、Edge、Safari、Firefox 移动端、隐私窗口和容器执行端适配。其他设备自行准备 API 不等同于本规格承诺新增浏览器支持。
- 本次规格发布不包含实现、代码提交或推送、生产部署、修改真实 API 配置、真实模型调用或扩展商店发布。

## Further Notes

- 用户确认不要额外后台助手；“OpenAI 兼容协议”是接口形式，真正的本机执行进程为已安装的 Firefox 插件。云端生成 prompt 和管理业务，不再负责模型传输。
- 用户明确取消手动转交，要求由发起者承担分类责任；本规格据此将执行责任绑定到发起设备，而不是同账号任一在线设备。
- 用户指出已有断点续传。当前代码确有独立批次、共享分类体系缓存、租约重试和结果版本保护；新增需求是跨浏览器执行阶段、完整本机响应缓存、幂等回传及通用结果提交的崩溃窗口保护，不能声称现有模型 HTTP 请求已经支持中途续传。
- 已有本机网关的模型目录和连接信息曾只读核验，但尚未据此验证真实生成、结构化输出或分类质量。具体网关和模型不是写死的产品依赖，不在规格或 Issue 中记录任何真实密钥。
- 本规格取代原 Firefox 规格中“模型请求由服务器执行”“插件不保存任何本机 AI 配置”“服务器接受任务后无须 Firefox 继续参与分类”的假设；保留 URL／标题提交、云端收藏、重复保护、现有认证和入口审批语义。
- 业务状态继续遵守运行身份与业务收藏库隔离。既有本机管理工具的人工审批边界继续生效，不因迁移模型调用而赋予自动确认能力。
- Issue #8 的已部署功能与尚未完成的验收记录保留。本规格作为后续架构变更，不将旧功能记录标记为新链路已经实现，也不关闭未完成验收。
- 文中测试均为后续验收要求，不代表本机执行链路、暂停状态、迁移或正式插件升级已经完成。
