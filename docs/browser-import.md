# 浏览器书签导入

2026-10-18 更新。Firefox / Chrome Netscape HTML 先预览，再确认准确工作量后执行。

## 工作流程

1. 上传和解析；跳过重复和无效条目，显示网站数、最多双端抓取任务数及 AI 请求数。预览阶段不创建网站、抓取或 AI 任务。用户确认与内容、任务量、库 epoch 绑定的短时签名后执行；保留既有记录的标签、备注、刷新间隔和历史。
2. 新网站先落到未分类，保存浏览器原目录作为参照；同事务登记桌面和手机抓取任务，避免重复的元数据采集。
3. 等整个批次的双端任务成功、失败或取消；retry_wait 尚未完成。抓取维持有界重试，失败仍参加分类；桌面失败而手机成功时使用手机元数据。
4. 全部抓取完成后才调用已验证的 AI，每次最多十站。没有可用 AI 就跳过；服务中途失败停止剩余自动调用，保留已有建议，其余网站留下可人工编辑的未分类条目。原目录、标题、网址和有限正文作为分类数据。
5. 自动流程完成后进度变成 100%，移除进度条。在“导入与备份”页时打开分类校对弹窗；在其他页时保持当前操作，回到导入页才打开。
6. 校对弹窗修改、确认或驳回目标。确认才建立目录、移动网站。抓取失败和未进行 AI 分类分别标注；关闭不自动重开，通过“查看建议”主动打开。

独立分类校对页面和导航已移除。导入、单站分类和文件夹重新分类共用弹窗。旧 /classification 地址跳转到导入页，网站详情和分类任务提供“查看建议”。

## 持久化与进度

ImportBatch.stage 为 records → captures → classification → review；state=succeeded 仅表示自动工作结束，不表示人工批准。capture_group 和 classification_group 记录依赖，阶段转换在 worker 中以事务执行，重启可继续推进。review_notified 记录一次自动提醒，跨刷新和设备保留。

进度按记录 0–10%、双端抓取 10–80%、AI 80–99% 计算；达到可校对状态为 100%。同时显示实际设备任务计数和失败网站数，百分比不是剩余时间估算。

每次最多执行 1000 个有效网站、2000 个双端抓取任务和 101 次 AI 请求（含最多一次共享目录规划）。AI 配额在实际请求前持久扣减，包含失败请求和手动重试；抓取任务各自仍有有界重试。一次只执行一个导入；超过配额完整拒绝，用户拆分文件后重试，不截断条目。解析器的十万条安全上限不作为执行配额。升级时旧未确认工作回到可见预览，已导入记录与快照保留。

自有格式使用 SQLite + HTML 快照，ZIP64 备份包含配置和历史。旧版 0001_initial 的精确已知 schema 可在隔离目录中迁移升级后恢复；任意修改的 schema 仍拒绝。

## 验证

- library.tests.ImportWorkflowTests：严格阶段依赖、重试等待、AI 不可用/部分成功、重复导入、人工批准及提醒持久化。
- tests/portability/test_schema_upgrade.py：旧版备份升级及候选文件 hash 重新绑定。
- tests/run_import_workflow_server.py + tests/import_workflow_ui.py：真实 HTTP、数据库队列、归档发布、浏览器进度和弹窗、手机布局、校对与确认。网页抓取为受控归档样本，AI 使用本地协议服务；本项不验证第三方网站采集保真或真实模型分类质量。

用户提供的个人书签文件未自动执行导入，测试使用独立库和构造 HTML。
